# 웹 수정 스튜디오 — 설계 (2026-08-03)

한글패치 유저가 브라우저에서 직접 오역·미번역을 검색→수정→빌드하고,
고친 걸 공유하거나 원버튼으로 제보할 수 있는 정적 웹앱. GitHub Pages 호스팅.

## 배경

- 지금 배포판은 번역표(jsonl) + 빌드.py(Python 3.10 + rubymarshal 전제)로
  수정이 가능하지만 진입장벽이 높다.
- 유지자 전용 fixgui.py(translate/fixgui.py, 로컬 HTTP GUI)가 있으나 repo
  경로·로컬 빌드에 묶여 배포 불가.
- 제보는 산발적(커뮤니티 댓글)이고 실시간 대응이 안 된다.

## 결정 사항

- **형태**: 정적 HTML 한 장 + pyodide(파이썬 WASM). 서버 없음, GitHub Pages.
- **편집 대상**: 번역표를 페이지에 동봉하지 않는다. 유저가
  `showDirectoryPicker`로 게임 폴더를 선택하면 `Data/korean.dat`를 그 자리에서
  읽어(export 로직 재사용) 편집 대상으로 삼는다. 패치 버전과 편집 대상이
  어긋날 수 없고, 새 패치 버전이 나와도 웹앱 무수정.
- **빌드**: 기존 빌드.py의 값-교체 로직을 pyodide에서 그대로 실행,
  korean.dat를 직접 다시 쓴다. 첫 빌드 때 `.bak` 백업 유지.
- **브라우저**: Chrome/Edge 전용(File System Access API + pyodide
  `mountNativeFS`). 페이지에 명시.
- **코드 재사용**: rubymarshal(순수 파이썬)·rubywrite·빌드/추출 코드를
  수정 최소로 vendor. 새 직렬화 코드는 쓰지 않는다.

## 화면 / 기능

fixgui.py의 검색·행 수정 UI를 이식한다(서버 왕복 제거로 오히려 단순해짐).

1. **폴더 선택** — 게임 폴더 지정, korean.dat 로드·절별 목록화.
2. **검색·수정** — 원문/번역 검색, 행 편집(v만), 마크업 코드(`\c[2]`, `\PN`,
   `{1}` 등) 훼손 시 경고. 수정 내역은 IndexedDB에 자동 보존.
3. **빌드** — 원버튼. 수정 행만 값 교체 후 korean.dat 재작성.
4. **내보내기** — 바뀐 행만 담은 고침 파일(jsonl, `{section, idx, k, v}`)
  다운로드. 커뮤니티 첨부용.
5. **가져오기** — 남의 고침 파일 열기 → k(원문) 일치 검사 후 병합.
  내 수정과 충돌하는 행은 나란히 보여주고 선택.
6. **제보(원버튼)** — 행 옆 [제보] 버튼. 누르는 즉시 백그라운드 전송
  (구글폼 formResponse POST, `mode:'no-cors'` — 페이지 안 열림).
  선택 입력란 하나(한 줄 코멘트/제안 번역). 전송 후 토스트 확인.

## 제보 페이로드

구글폼 필드(응답은 시트에 축적, 유지자가 수거해 정본 반영):

- section / idx / k(원문) / 현재 v / 제안·코멘트(선택)
- **패치 메타**: korean.dat 안의 버전 표식(아래) 또는 없으면 파일 SHA-256
  앞 12자 + 파일 크기
- 웹앱 버전

### 패치 버전 표식

translate/build.py가 빌드 시 korean.dat에 메타 항목(예: 시스템 절의
`__kr_patch__` 키에 `v6|2026-08-03` 형태)을 심는다. 웹앱은 이 키를 읽어
제보에 싣고, 없으면(v5 이전) 해시 폴백. 게임은 이 키를 조회하지 않으므로
동작 영향 없음 — 단, 빌드 왕복 검증이 키 추가를 허용하는지 확인 필요
(골격 검사 로직 조정 가능성).

## repo와의 관계

- 정본은 지금처럼 이 repo의 translate/ko/. 웹앱 유저의 고침·제보는 "제안"
  이고, 정본 반영은 유지자의 기존 워크플로(fixgui/fix.py)를 거친다.
- 웹앱 코드는 **별도 공개 repo**(Pages 호스팅). 번역표·게임 데이터·조인표는
  올리지 않는다 — 코드만이라 저작권 부담 없음.
- 구글폼/시트는 유지자 계정에 생성. entry ID들을 웹앱 설정에 기입.

## 범위 밖 (YAGNI)

- 계정·권한·실시간 동기화·서버 일체
- 화자 문맥(조인표) 표시 — 조인표는 repo 전용 데이터라 동봉하지 않음.
  필요해지면 익명화 축약본 동봉 검토.
- 게임 내 수정 모드(루비 스크립트 모드) — 추후 보조 수단으로 별도 검토.

## 리스크

- pyodide 첫 로드 수 MB(첫 방문 몇 초, 이후 캐시). CDN 로드.
- File System Access API로 게임 폴더 쓰기 시 브라우저가 권한 프롬프트를
  띄움 — 안내 문구 필요.
- 구글폼 no-cors POST는 성공 여부를 확인할 수 없음(opaque 응답) —
  "전송됨" 토스트는 낙관 표시임을 감수(실측 불가). 폼 entry ID가 바뀌면
  조용히 유실되므로 배포 전 실제 시트 도달 확인 필수.

## 검증

- 왕복: 원본 korean.dat → 웹앱 로드 → 무수정 빌드 → 바이트 비교(값 교체
  로직이 기존 빌드.py와 동일 출력인지).
- 수정 1행 → 빌드 → 게임에서 해당 대사 확인(실기 1회).
- 고침 파일 내보내기→새 세션 가져오기 왕복.
- 제보 버튼 → 시트 도달 실측.
