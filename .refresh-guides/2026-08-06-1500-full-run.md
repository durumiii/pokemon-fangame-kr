## 바로 할 일 — 전량 재번역 실행 (유지자 발사 승인만 받으면 됨)

구성은 확정됐다: **전부 B 새 번역 · effort=low → 기계 검증 → 선별 2층 → 선별분만
사람 판정.** 갈래 규칙(승인 장면 A)은 기각 — run에 --fresh만 쓴다.

```bash
cd pokemon-z
uv run translate/batch_pages.py plan            # 473페이지 4,248행 확인
uv run translate/batch_pages.py run --fresh --effort low     # ~$11, 산출 batch/page-out-fresh/
uv run translate/screen.py translate/batch/page-out-fresh    # 휴리스틱 선별 (무료)
uv run translate/screen_llm.py translate/batch/page-out-fresh  # 모델 선별 (~$9)
```
⚠ run은 out-dir에 있는 cid는 건너뛴다(재개 가능). 병렬 4워커, 전량 1~2시간 예상.
⚠ page-out-fresh 디렉토리 이름 확인 — run(pilot=False, fresh=True)의 실제 산출 경로는
`batch/page-out-fresh/`다(코드 out_dir 조립 참조).

## 판정·적용 흐름 (파일럿 3판에서 굳은 절차)

1. 선별분(screen.jsonl ∪ screen-llm.jsonl, 예상 200~600행)을 검수 페이지로 조립 —
   스크래치의 pilot3-review.html 꼴 재사용(장면 문맥·프롬프트 전문·메모·보류 포함).
   선별 안 된 행은 **자동 채택**(승인 줄 제외 — approved 표시 행은 현행 유지).
2. 판정 TSV 반영: id→(맵, fold(es))로 00-maps.jsonl 수정, validate.check로 확인,
   build.py + verify.py --strict, 커밋 꼬리표 `Edit-Source: human`.
3. 판정·자동 채택된 줄은 approved-lines.jsonl에, 판정 끝난 이벤트는
   approved-events.jsonl에 환류.
4. 자동 채택 전 최소 안전판: 반려(ok=false) 행은 현행 유지, 승인 줄(approved) 행도
   현행 유지 — 이 둘은 스크립트에서 걸러라.

## 헛디딘 것 (이번 세션 후반)

- 티켓 보고를 작업 뒤로 미뤄 위임 기회를 막았다 — 물음에는 답부터([[feedback-answer-first-then-work]]).
- 「번역 $7 vs 선별 $9」처럼 다른 어림을 나란히 놓아 오독을 만들었다 — 단가는 행당 실측으로.
- 서브 둘 다 티켓의 전제를 반증했다(기니아류는 이미 지시 받음 · 자동 본보기는 2%뿐) —
  전제부터 실측시키는 프롬프트가 옳았다.
