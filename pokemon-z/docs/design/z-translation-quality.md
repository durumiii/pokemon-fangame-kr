# Pokemon Z 번역 품질 개선 — 조사와 플랜

> 2026-08-01. 사용자 방향: ① 쉬운 것부터 — 인명 + 공식 용어 통일(본가 번역 DB 참고,
> 없으면 조사·창작), ② 인물별 말투 설정과 직역 냄새 제거는 해볼 만하되 **토큰이 많이
> 드는 만큼 품질과 비용을 미리 조사**할 것. 이 문서가 그 조사와 실행 계획이다.

## 재료 확보 상태 (전부 실측)

- **판독·되쓰기가 뚫렸다.** `korean.dat`은 Essentials 다국어 포맷(절 24개,
  `MessageTypes` 상수와 1:1 — 1=종, 5=기술, 7=도구, 10=특성, 14=NPC명, 19=지명,
  21=맵이름, 23=스크립트 문장). 대사 쌍은 OrderedHash의 중첩 Marshal(`[keys, values]`)에
  있고, `fanlib.rubywrite`로 **왕복 구조 일치 + 값 교체 후 재판독까지 검증됐다.**
- **코퍼스 추출 완료**: 스크래치패드 `korean_corpus.json`. 스페인어 원문↔한국어 쌍
  **20,597건**(맵 대사 13,770 + 스크립트 문장 6,827) + 이름 목록형 8,512건.
  ES 1,241,310자 · KO 746,940자, 번역문 길이 중앙값 42자.
- **산출 경로**: 갱신한 `korean.dat`을 「한글패치 통합」 모드(보관소)에 넣고 라이브러리로
  재설치. 원본은 모드의 정본 사본이 보존한다.

## 번역 정본 — korean.dat는 이제 빌드 산출물이다 (2026-08-02)

**정본은 repo의 `mod/z/translate/ko/`다** — 절별 JSONL, 한 줄이 한 문장(원문+한국어),
줄 순서가 dat의 자리 순서. `build.py`가 정본에서 korean.dat를 구워 왕복 검증 후
보관소·게임에 앉힌다. **앞으로 번역 수정은 ko/ 파일에만 하고 build로 굽는다** —
dat를 직접 문지르는 스크립트를 부득이 쓰면 직후에 `export.py`로 정본을 재동기화한다.
게임 업데이트로 원문이 바뀌면 build가 골격 불일치로 멈추고, 그때도 export부터.
이 구조 덕에 수정·검수·LLM 재번역이 전부 git 줄 단위 diff로 관리된다.

## 갈래 1 — 인명 + 공식 용어 (싸고 체감 큰 쪽)

### 인명 (가장 큰 구멍)

- NPC 이름 절(14) **362건 전원 로마자**. 상위 20명이 대사 속에 **3,760회** 등장
  (Crisanto 771 · Melia 543 · Olivier 418 · Mirra 323 · Alca 290 …).
  대사 20,597줄 중 로마자 낱말 포함이 6,814줄 — 대부분 이 인명들이다.
- 방법: ① LLM 한 번으로 362명 음차안 생성(스페인어/프랑스어 발음 기준 병기) →
  ② 사용자 검수(상위 빈도부터) → ③ 기계 적용 — 절14 교체 + 대사 내 문자열 치환.
  치환은 `<b>이름</b>`·`이름:` 패턴이 대부분이라 안전하고, 짧은 이름은 단어 경계를
  검사한다. 비용은 사실상 0(호출 한두 번).
- 지명도 같은 틀: 절19는 이미 번역됨(1번도로), 절20에 혼혈("Merlot 저택") 잔존 — 함께 검수.

### 공식 용어

- **일반 용어는 생각보다 건강하다**(실측): Centro Pokémon→포켓몬센터 52/54,
  entrenador→트레이너 지배적, Poké Ball→몬스터볼. 갈라진 것은 `combate`
  (배틀 159 · 시합 7 · 대결 6)과 따옴표 스타일 정도 — 규칙 치환으로 통일 가능.
- **게임 데이터 명칭은 본가 DB(우리 Wishing Star 판독 `packed.json`, 검산된 한국어명)와
  전수 대조했다**: 종 18건 · 기술 41건 · 특성 32건 불일치. 내용은 세 부류가 섞여 있다 —
  옛 공식명(→현행 공식명으로 갱신), Z 창작 콘텐츠(→포켓몬 번역 스타일로 창작), 표기
  변형(공백·구판 표기). 실행 시 한 건씩 분류한다. **도구 905건 전부 불일치는 대조
  코드가 packed의 도구 행 구조를 잘못 짚었을 가능성이 커서 무효 — 다시 잰다.**
- 이 명칭들은 대사 본문에도 등장하므로, 명칭 확정 후 대사 쪽도 같은 치환을 태운다.

## 갈래 2 — 인물별 말투 + 직역 제거 (LLM 배치)

### 재료

- **화자 태그가 이미 붙어 있다**: `<b>이름:</b>` 프리픽스가 3,398줄, 화자 199명.
  상위 15명이 태그 대사의 약 72%를 덮는다 — **말투표는 상위 ~20명 + 기본값 셋**
  (일반 NPC 반말/해요체, 시스템 문구 평서)이면 충분하다.
- 무태그 대사는 맵·인접 대사 문맥으로 화자를 추정하거나 기본값을 쓴다.
- **보존해야 하는 마크업**(기계 검증 가능): `<b>` 6,406 · `\c[n]` 5,336 · `<i>` 579 ·
  `\PN` 486 · `\se`·`\sh`·`\wtnp[n]` 등. 재작성 후 원문과 마크업 종류·수 일치를
  기계로 검사하고, 불일치는 자동 반려·재시도한다.
- 길이 제약: 원문 대비 과도한 팽창(>1.4배)을 반려 기준에 넣는다(대사창 폭).

### 파이프라인 설계 (개요)

1. 맵 단위로 대사를 묶어(문맥 유지) 배치 요청 생성 — 쌍 30~60개/요청, 프롬프트에
   용어집(갈래 1 산출) + 화자 말투표 + 규칙 첨부.
2. 구조화 출력(스키마 강제)으로 `[{id, ko}]`를 받는다.
3. 기계 검증(마크업·길이·플레이스홀더) → 불합격만 재시도.
4. 표본 감사: 무작위 표본을 원문 대조(뜻 보존) — humanize-korean의
   content-fidelity 개념을 축소 적용.
5. `korean.dat` 재조립 → 모드 갱신 → 실기 확인.

### 비용 (2026-08-02 확정 — 아래 옛 산정은 폐기)

경로는 **llmgateway + gemini-3.6-flash + reasoning_effort=minimal**로 확정됐고,
실측 비용은 **전량 초벌 ~$8(상한 $10)**이다. 산정 근거·설정·범위는 실행 승인 문서
[`z-batch-run-proposal.md`](z-batch-run-proposal.md)가 정본이다. 애초 이 자리에 있던
Anthropic Batch API 기준 표($4~19)는 그 결정 이전의 산정이라 지웠다 — 씽킹 과금
발견과 effort 실측이 그 표를 무효로 만들었다(같은 문서 4절).

### 품질×비용 사전 검증 — 파일럿 (플랜의 첫 실행 단계)

전량을 돌리기 전에 **표본 200쌍**(화자·문체 다양하게)을 모델 2~3개(예: Sonnet 5 배치 /
Haiku 4.5 / 저가 게이트웨이 모델)로 돌려 나란히 놓고 사용자가 눈으로 고른다.
파일럿 비용은 모델당 $0.1 미만. 여기서 모델·프롬프트·반려 기준을 굳힌 뒤 전량 배치.

## 실기 관찰 첫 소견 (2026-08-02 사용자 — 다음 세션의 표적)
