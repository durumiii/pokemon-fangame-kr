# Z 컨트롤러 UX 모드 설계 (M-22)

> 2026-08-02 합의. Pokémon Z Fangame(mkxp-z 구판 · 루비 1.8.7)의 컨트롤러 지원을
> 스크립트 주입 모드 하나로 끌어올린다. 표기 기준은 **Xbox 배치**(사용자 확정).

## 배경 실측 (2026-08-02, 전부 실물 확인)

- 실행기는 SDL 게임컨트롤러 DB와 F1 바인딩 메뉴를 내장한다(바이너리 문자열
  `Press key or joystick button for "%s"` · `keybindings.mkxp`). 기본 조작과
  일시정지 메뉴의 회복·비행·레이더·터보는 가상 버튼(`Input::X`·`Y`·`Z`·`L`)을
  읽어서 패드가 **이미 닿는다** — 사용자 실기 관측(X·LB·RB·RS클릭)과 일치.
- 안 닿는 자리는 둘뿐이다.
  - **등록 아이템**: `056_Scene_Map.rb:142`가 가상 `Input::F5`를 읽는데 기본
    패드 매핑이 그 버튼에 없다.
  - **이름 입력 완료**: `000_Settings.rb:359`의 `USEKEYBOARDTEXTENTRY = true`라
    실키보드 타이핑 화면(`PokemonEntryScene#pbEntry1`)이 쓰이고, 완료가
    `Input.triggerex?(:RETURN)`(키보드 직독) 한 줄이다(`053_TextEntry.rb:946`).
- 커서: 이 빌드는 `show_cursor=`를 루비에 노출한다(바이너리 심볼 실측). 마우스
  UI(`$mouse`/`Game_Mouse`)는 정의가 없는 죽은 코드라 상시 숨김에 잃는 것이 없다.
- 키 표기 자리는 셋 — 도움말 화면의 키보드 키 그림 다섯 장
  (`Graphics/Pictures/help*key.png`, `058_Scene_Controls.rb`), 일시정지 메뉴의
  `[A] Curar` 식 하드코딩 힌트(`206_Menu Mejorado.rb:1466` 근방), 이름 입력 안내.
- 게임 자체 키 설정 화면(`169_Controles.rb`)은 키보드 VK 전용 레이어다 —
  건드리지 않는다.

## 만드는 것: 주입 모드 `Controller UX Z`

`mod/z/mods/Controller UX Z/`, `inject.py` 경유, 루비 1.8.7 문법, 보관소
(`/mnt/d/GameVault/mods/Pokemon Z Fangame/`) 흐름. 네 조각:

1. **커서 자동 숨김** — 마우스가 움직이면 보이고 2초(120프레임) 쉬면 숨긴다
   (`mouse_x/y` 폴링, `Input.update` alias — 2026-08-02 사용자 요구로 상시 숨김에서
   변경). 「마지막 입력이 패드인가」는 가상 버튼 층이 키보드·패드를 합쳐 출처가
   스크립트에 안 내려오므로 못 가린다 — 마우스 유휴가 그 대용이다.
2. **이름 입력 패드 연동** — `pbEntry1`에 alias로 패드 확인(가상 C) 경로 추가.
   **같은 프레임에 글자 입력이 있었으면 무시하는 가드**를 넣어 타이핑 키와의
   충돌을 차단한다(가상 C의 키보드 바인딩이 이름에 들어갈 글쇠일 수 있다).
   취소도 가상 B로. 키보드 RETURN/ESC 경로는 그대로 둔다.
3. **등록 아이템 패드 연동** — 필드 판정에 비는 가상 버튼 하나를 추가로 받게
   alias. 키보드 F5 유지. 어느 버튼이 비는지는 아래 사전 실측이 정한다.
4. **표기 Xbox화** — 일시정지 메뉴 힌트 문자열을 실제 패드 버튼 표기로 교체
   (`UI Text KR`식 그리기 훅), 도움말 화면 키 그림 다섯 장을 Xbox 글리프 PNG로
   교체(에셋 교체 — `replaces_crc`), 이름 입력 안내 문구 갱신.

## 사전 실측 (착수 게이트)

**기본 패드→가상 버튼 대응표.** 게임에서 F1 바인딩 화면을 열어 목록을 읽는다
(사용자 한 번, 스크린샷이면 충분). 이 표가 ④의 표기 전부와 ③의 버튼 자리를
정한다 — 없이 그리면 표기를 틀린다. 관측 단서: RS클릭이 터보(가상 `L`)에
닿는 걸 보면 기본 매핑이 넓게 걸쳐 있다.

## 안 하는 것 (비용으로 적어 둔다)

- **바인딩 실시간 반영**: 엔진이 바인딩 조회 API를 루비에 안 내놨다(심볼 전수
  확인 — 입력 쪽은 `raw_key_states`·`text_input`·`mouse_x/y`·`show_cursor=`뿐).
  우회로는 F1이 저장하는 `keybindings.mkxp`를 부팅·mtime 폴링으로 파싱하는 것 —
  포맷(버전 헤더 + 소스/타깃 구조체, union 패딩)을 이 판본 mkxp 소스와 실물
  파일로 검증해야 한다. 혼자 쓰는 모드라 값어치가 "리바인딩을 실제로 하는가"에
  매달리므로, 그것이 관측되면 연다.
- 게임 자체 키 설정 화면(169)의 컨트롤러화 — 위 레이어와 별개 물건이고 수요 없음.
- Steam Input 등 외부 매퍼 — 입력은 되지만 표기 문제가 그대로 남는다.

## 검증

- 이름 입력은 UI 흐름 수정이므로 **프로브로 수명주기를 굴린 뒤 배달한다**
  (mod/AGENTS.md 규율): 키보드 타이핑 중 가상 C 동시 발화에 완료가 안 새는
  음성 케이스 + 패드 확인으로 완료되는 양성 케이스.
- 커서·등록 아이템·표기는 실기 확인(사용자 5분).
