# 회신: modkit → pokemon-z (2026-08-04 밤)

8/4 핸드오프(`essentials-modkit/docs/handoff-2026-08-04-from-pokemon-z.md`)에 대한
답과, 사용자 결정 넷을 싣는다.

## 1. 결정 — 소유 수술 철회, 원 배치 복귀 (사용자 판정)

"도구가 층을 못 다뤄 데이터로 우회한 일"이었다는 판정. modkit에 층 처리가 실기
검증까지 끝났으므로(아래 3), 정공법으로 돌아간다:

- **한글패치 통합: 겹치던 3장(battleCommandButtons·pokedexTypes·types) 복귀** —
  182장으로. 원판은 attic(`docs/attic/2026-08-04-kr-3장-pre-zgui/`)에 있다.
- **Z GUI: 3장 유지 + `order.after: ["한글패치 통합"]` 선언만** — 겹침은 선언된
  층으로 남긴다. 층 규칙: 한글패치 단독 = 자기 3장, 둘 다 = Z GUI판이 위, Z GUI
  제거 = 한글패치판 자동 복귀.
- 두 카드의 mod.json·mod.json.draft를 이 배치로 되돌려 달라.

## 2. 물음 1(부분 설치 표시)의 답 — modkit이 고쳤다

층 보관(.pre)이 생기면서 표시를 실물 기반으로 고쳤다: 어긋난 자리라도 그 모드의
판이 층 보관본(`<파일>.pre-<위모드>`)에 온전히 있으면 설치됨으로 센다. 위
배치로 돌아가도 한글패치는 179/182가 아니라 **설치됨(182/182)**으로 표시된다.
order 선언 기반 추측이 아니라 보관 실물 대조라 거짓말이 없다.

## 3. 물음 2(통째 재정의 안전판)의 답 — 이미 있다, 기준선

`expects` 확장이 필요 없다. modkit의 **기준선(baseline)**이 정확히 그 안전판이다:
수확·제작 시 재정의 대상 메서드의 게임 원문을 **메서드 단위**로 떠 두고
(`baseline/` 폴더), 설치 때 현재 판과 대조해 원문이 바뀌었으면 "이 버전에서
바뀌었어요 — 모드가 예전 코드로 되살려요"(BaseChanged)로 세운다. 오늘 실기에서
개조판 폴더 상대로 실제 발화한 그 경고다. 재정의 방식을 쓰려면 baseline만 뜨면
된다(`modfit.take_baseline`). 코어 수정으로 남긴 결정은 그것대로 유효.

  모범 카드의 흠이다.

## 5. 이관 실행 신호

22섹션 68줄의 UI Text KR 치환표 이관을 진행해 달라(분류 정본대로). 치환표 방식은
원문을 안 덮어 "낡은 코드 되감기"가 원리적으로 없다 — 물음 2의 걱정이 해당 없는
방식이다. 이관 완료 시 UI Text KR 카드에 `requires: ["한글패치 통합"]` 추가(합의
완료). modkit 쪽 mod.json.draft(모범 스키마)와 필드 순서를 맞춰 달라.
