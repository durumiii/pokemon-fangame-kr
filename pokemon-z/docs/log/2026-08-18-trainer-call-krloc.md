# 전투 호출 대사에 좌표 길을 냈다 — 수술 자리는 `_I` 하나 (2026-08-18)

Z-73의 마지막 남은 항목. 전투 호출(`pbTrainerBattle`) 대사는 좌표 조회 밖이라 화자가
갈려도 못 가르던 자리였다. 조회 지점을 둘 더 수술해야 하는 줄 알았는데 실측해 보니
**메서드 하나**였다.

## 어디로 가는가 — 실측

전투 호출 대사는 101 메시지가 아니라 **조건 분기(111)의 스크립트 인자**에 있다.

    IF script: pbTrainerBattle(PBTrainers::MARIO,"Mariano",_I("¡Mamma mia! ¡Buen entrenamiento!"),false,1,false)

`_I`는 게임 소스에서 두 줄이다(`Intl_Messages` 754~756).

    def _I(str)
      return _MAPINTL($game_map.map_id,str)
    end

그 스크립트를 돌리는 것은 `Interpreter#pbExecuteScript`의 `eval`이다(`Interpreter`
241~244). `command_111`은 코드 12(스크립트)에서 그것을 부르고(793~794), `@index`는 아직
안 밀린 상태다(`execute_command`가 현재 명령을 가리킨 채 분기한다, 291~302).

그래서 `_I`가 불릴 때 **`@map_id`·`@event_id`·`@index` 셋이 다 손에 잡힌다.** 좌표
열쇠에 필요한 값이 그 자리에 이미 있다.

## 루비 1.8.7 실물 판정

최상위 `def`가 `eval` 안에서 인터프리터의 인스턴스 변수를 보는지는 언어 감각으로
단정할 자리가 아니라 게임 실행기로 쟀다(`share/qa-trainerloc.rb`, 러너와 돌리는 법은
같은 이름의 `-runner.rb` 머리에). arm 다섯이 다 통과했다.

| arm | 재는 것 | 결과 |
|---|---|---|
| P·Q | `_I` 자격의 최상위 def가 보는 값 | `[25, 38, 7, "Interpreter"]` — 기대와 같다. `@index` 7이 정본 자리 `m25.e38.p0.c7`의 c와 같다 |
| R | 지금 판의 `_I`가 한국어를 내나 | `"맘마미아! 정말 좋은 훈련이었어!"` — 경로가 살아 있다 |
| S | 수술본에서 좌표 값이 이기나 | 맵 값 `"…시작하겠어?"` 위로 좌표 값 `"…시작할까요?"`가 나왔다 |
| T | 좌표 없는 자리는 그대로인가 | 옛 값 그대로 |
| U | 인터프리터 밖에서 부르면 | 안 깨지고 맵 조회로 떨어진다 |

S가 쓴 맵155(훈련소) 이벤트4 c1은 101 대사 자리다 — 전투 호출 자리가 아니라 **좌표
항목이 이미 깔려 있어 조회 승패를 가릴 수 있는 자리**라서 골랐다. 재는 것은 `_I`의 조회
우선순위이지 그 자리의 동작이 아니다.

함정 하나를 이 시험에서 만났다. 절42를 다시 `eval`하면 `MessageTypes`가 새로 서면서
`@@messages`가 비어, 수술본 arm이 전부 스페인어를 냈다. 시험대에서 절을 다시 태울 때는
`loadMessageFile`을 함께 다시 부른다.

## 얹은 것

`share/patch_intl.py`에 EDIT 하나. 인터프리터가 아닌 데서 불리면 `@map_id`가 nil이라 옛
조회로 그대로 떨어진다. 폴백의 기준 맵도 `@map_id`로 내렸다 — 맵 대사에서 이미 고친
전이 결함(도착 맵으로 조회)이 이 경로에는 남아 있었다. 공통 이벤트는 `setup`이 셋째
인자를 안 받아 `@map_id`가 현재 맵이 되므로 동작이 그대로다.

얹기만 하는 수술이라 뒤따르는 `_MAPINTL` 정의까지 앵커에 물려 멱등을 세웠다(2026-08-17에
두 번 얹힌 사고와 같은 함정). 확인한 것 셋 — 옛 자구가 새 자구의 부분 문자열이 아니고,
설치본 절에 옛 자구가 정확히 한 번 있고 새 자구는 없으며, 다른 EDIT과 앵커가 겹치지 않는다.
