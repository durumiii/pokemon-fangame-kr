## 유지자 판정 (2026-08-09)

- 새 모드 둘 중 **Type Matchup**은 세 갈래 합본에 기본 동봉, **Debug Toggle**은
  디버그 추가판에 싣고 그 판의 기존 디버그 편집을 대신한다.
- **모드 이름 끝의 `Z`를 뗀다** — `Type Matchup Z`·`Debug Toggle Z` → `Type Matchup`·
  `Debug Toggle`(저장소·보관소·설치본의 주입 섹션 이름 모두).
- 디버그판은 **켜진 채로 나가고 토글이 그 위에 얹힌다** — Debug Toggle의 키 폴링은
  Win32API라 모바일에서 안 먹어서, 단순 대체하면 Runa에서 디버그를 못 연다.
- 배포 전에 **mkxp-z 로컬 시험대를 세운다**(아래).

> ⚠ 위 판정 중 디버그 모드 부분은 **Z-48로 갈렸다**(2026-08-13). 모드 이름은
> 「디버그 모드」 하나로 합쳤고(구 `Debug Toggle`·구 `디버그 모드` 삭제), 키는 P,
> 판정은 Win32API가 아니라 엔진의 `Input.triggerex?`다 — 모바일에서도 먹으므로
> 「키 폴링이 안 먹어서 켜진 채로 내보낸다」는 이유는 더 서지 않는다. 켜진 채로
> 내보내는 것 자체는 그대로 둔다(타이틀을 건너뛰는 부작용은 [Z-48](Z-48.md)에 적었다).

## mkxp-z 시험대 (P-2) — 섰고, 열 자리를 잡아 고쳤다

데스크탑 mkxp-z 신판(루비 3.1)에 합본을 얹어 유지자가 직접 밟았다. 루비 3에서 죽던
자리 열을 잡아 전부 호환 수술로 등재했고(뿌리형 셋 포함), 시험대에서 배틀·포획·
파티 만석 포획·박스 보내기까지 통과했다. 원판(PC, mkxp-z 32비트·루비 1.8.7)에서도
같은 코어로 정상 동작 — 유지자 확인. 자리별 근거·시험대 세우는 법은
[시험대 기록](../log/research/2026-08-09-mkxpz-bench.md).

⚠ Runa 실기는 여전히 미확인이다. 시험대는 같은 엔진의 데스크탑 판이라 iOS 포트만의
손질은 재현하지 못한다.

## 배포 재료 (지금 갖춰져 있음 — 낼 때 다시 만든다)

유지자 판단으로 **이번엔 안 낸다** — 한국어 번역을 더 고친 뒤 합쳐서 낼 것이다.
그때 다른 세션이 이어받을 수 있게 상태를 적어 둔다.

- 조립기·판 번호·주입 목록은 v5.3으로 다 서 있다. `share/dist/`의 zip 네 벌은
  2026-08-09 17:41 판이다.
- ⚠ **정본(`translate/ko/`)이 바뀌면 그 zip은 낡은다.** 낼 때 순서는 셋:
  `uv run runa/make-patch-mod.py`(코어에 최신 번역표) →
  `uv run share/patch_ruby_compat.py`(호환 수술 재부착) →
  `uv run share/make_package.py --variant runa --font <갈래> --zip` 세 갈래 +
  `--variant runa-debug --zip`.
- 릴리스 노트는 태그 diff에서 뽑고([release](../guides/release.md)), **릴리스는
  유지자 승인 후.** 판 번호를 v5.3에서 올릴지도 그때 정한다.
