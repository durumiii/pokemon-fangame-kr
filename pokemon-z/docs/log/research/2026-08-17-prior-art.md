# 우리 앞의 바퀴들 — 번역 정본 구조의 선례 조사 (2026-08-17)

Z-53 설계에 앞서 「이미 있는 것을 다시 만들고 있지 않은가」를 재려고 넷을 조사했다.
표준 포맷 · 게임 엔진 파이프라인 · 팬번역 개인 구조 · 런타임 자동 번역기.

**조사 목표는 완성된 도구를 찾는 것이 아니라 우리가 이름 붙이려는 것에 이미 이름이 있는지
보는 것이었다**(유지자: 「내가 진짜 원하는 바퀴는 대체로 아직 없거나, 나 같은 인간들이
혼자서만 쓰고 있더라」). 「없더라」도 결과로 취급했다.

## 한 문장 요약

**제품을 가진 쪽은 자기가 부여한 키로 찾고, 못 가진 쪽은 원문으로 찾다가 충돌을 사후에
사람이 가른다.** 우리는 소스를 가졌으면서 못 가진 쪽 방식을 쓰고 있었다.

## 1. 표준 포맷 — 자리를 어떻게 잡나

| 포맷 | 무엇이 정체성인가 | 같은 원문·다른 값 |
|---|---|---|
| gettext PO | **원문(msgid) 자체** | `msgctxt` — 원문 앞에 붙는 자유 문자열. msgctxt+msgid가 유일해야 한다 |
| XLIFF 2.x | `unit id` — 도구가 부여, 파일 안에서 유일. `resname`으로 원본 리소스 키를 따로 둘 수 있다 | id가 다르면 애초에 다른 항목 |
| Fluent | 메시지 **키** | 문제 자체가 안 생김 |
| Android | `<string name>` | 키를 새로 만드는 것이 관례 |
| iOS String Catalog | JSON의 키 | 상동 |
| TMX · TBX | 번역 메모리 교환용 · 용어집 — 제품에 반영되는 살아 있는 문자열 포맷이 아니다 | 해당 없음 |
| ICU MessageFormat | 파일 스키마가 아니라 **문자열 안 문법**이라 층위가 다르다 | 해당 없음 |

**요즘 포맷은 이 문제를 풀지 않고 피한다.** 원문이 아니라 키로 식별하니 갈릴 일이 없다.
원문을 열쇠로 쓰면서 맥락으로 가르는 것은 gettext 계열뿐이고, 그 장치가 `msgctxt`다.

**우리는 그 우회를 못 한다** — 게임이 원문 문자열로 조회하기 때문이다. 즉 구조적으로
gettext 갈래에 서 있고, 그것은 **제품 소스를 통제하지 못할 때 강제되는 자리**다.

### 이름이 이미 있는 것들

- **맥락 구분 = `msgctxt`.** Godot이 gettext에서 가져다 쓰고 공식 문서에 예제가 있다.
  새 말을 지을 이유가 없다.
- **「이 자리는 번역 대상이 아니다」** — 안드로이드 `translatable="false"`, iOS
  `shouldTranslate`. 안드로이드는 린트가 어기면 오류를 낸다.
- **유래** — W3C의 ITS가 **provenance**(누가 이 값을 만들었나)와 **MT confidence**
  (기계 번역의 자기 신뢰도)를 별도 데이터 범주로 정의해 뒀다.
- **「근사치라 재검토 필요」** — gettext의 `fuzzy` 플래그. **Godot은 fuzzy가 붙은 문자열을
  아예 게임에서 안 읽는다.**
- **작업 상태 축** — XLIFF의 `state`(초기 · 번역됨 · 검토됨 · 최종). 우리 승인 줄·승인
  이벤트가 하는 일인데 우리는 그걸 값에 붙이지 않고 별도 파일로 갖고 있다.

## 2. 게임 엔진 — 정체성과 원문을 나눈다

| 시스템 | 정체성 | 원문의 쓰임 |
|---|---|---|
| Unity Localization | 정수 **Key Id**(이름과 분리 저장) | 이름을 바꿔도 참조가 안 깨진다 |
| Unreal | **Namespace + Key** | Source String은 **번역이 낡았는지 판정하는 검증용**(stale translation validation) |
| Ren'Py | **라벨 + 문장에서 생성한 해시 ID**. `id` 절로 수동 고정 가능 | 위치가 곧 맥락 |
| Godot | 원문 또는 별도 ID(공식은 후자 권장) | msgctxt 지원 |
| 베데스다 모드 번역(xTranslator) | **FormID + EDID + 레코드:필드** | 레코드가 곧 맥락 |
| 파라독스 | 자유 문자열 키 | 언어별 파일 통째 분리 |

**두 가지를 배웠다.**

**하나 — 정체성과 원문을 나누고 원문은 낡음 판정에 쓴다.** Unity와 Unreal이 공통으로
그렇다. 우리가 자리표에 원문을 두려던 이유는 「번호 밀림을 잡으려고」였는데, 같은 필드가
훨씬 큰 일을 한다. **원작이 패치돼 스페인어가 바뀌면 그 줄의 번역이 낡았다고 자동으로
알 수 있다.** 지금 우리는 그걸 아예 못 잡는다.

**둘 — 우리와 처지가 같은 두 사례가 좌표를 정체성으로 삼았다.** Ren'Py의 라벨+문장 해시와
베데스다 쪽의 FormID+레코드:필드다. 특히 후자는 바이너리 레코드뿐이고 소스 코드라는 층이
아예 없는데, 그래서 **좌표와 필드 이름**을 키로 삼았다. 서로 모르는 둘이 같은 처지에서
같은 답을 냈다는 것이 좌표 방식의 근거로는 가장 단단하다.

**그림 속 글자**는 Unity가 텍스트 테이블과 **별도 자산 테이블**로 빼되 로케일 전환
장치는 공유하게 해 뒀다. 텍스트 스키마에 억지로 끼워 넣지 말라는 선례다.

**화자·말투를 1급 필드로 둔 엔진은 조사 범위에 없었다.** Ren'Py조차 화자를 별도 필드가
아니라 대사 덩어리에 통째로 흡수시킨다. 조사자가 「조사 범위 밖일 수 있다」고 유보했다.

## 3. 런타임 자동 번역기 — 원문 열쇠의 끝

유니티 게임용 자동 번역 플러그인은 문자열이 화면에 그려지기 직전, 텍스트 컴포넌트에
값이 대입되는 지점을 가로챈다. README가 스스로 이렇게 적는다 — **「가장 단순한 형태로
말하면 이 플러그인은 번역 안 된 문자열의 사전이다.」** 공백 차이 네 가지만 정규화해 찾는다.

맥락을 가르는 수단은 **씬 단위 스코프** 하나뿐이고, 문서가 **「번역 충돌을 피하는 데만
써야 한다」**고 못 박는다. 같은 씬 안에서 같은 원문이 두 뜻이면 못 가른다.

Ren'Py도 **UI 문자열은 원문이 열쇠**라 같은 벽을 만난다. 공식 해법은 **원본에 안 보이는
구분 태그를 사람이 심는 것**이다 — `"New"` · `"New{#project}"` · `"New{#game}"`. 도구가
알아서 가르는 게 아니라 저작 단계에서 미리 대비하는 구조다.

**훔칠 것 둘.**
- **사람 파일이 기계 파일을 언제나 이긴다.** 자동 생성 캐시와 사람 수정을 별도 파일로
  두고 우선순위를 코드에 박아 뒀다. 자동 생성분을 잘라 다른 파일로 옮기는 행위 자체가
  「확정」 표시가 된다.
- **좌표를 못 쓰는 자리를 위한 구분 태그.** 우리도 절23처럼 자리 없이 원문만 있는 공용
  문자열 풀이 있어 좌표 키가 성립하지 않는다. 최후 수단을 스키마에 미리 자리 잡아 둔다.

## 4. 팬번역 — 우리와 같은 문제를 이미 푼 사람

`Waiyakorn1879/for-the-plot`. Ren'Py 비주얼노벨을 LLM으로 태국어 번역하는 스킬 모음이다.
**경어가 있는 언어로, 남이 만든 게임을, 작가 없이 번역한다** — 우리와 처지가 같다.

### 관계쌍이 축이다

화자 레코드에 **`to` 맵**이 있다. 상대 화자를 키로 잡아 **그 관계에서만 쓰는 1인칭과
2인칭을 다시 정의**한다. 주인공이 평소엔 거친 1인칭을 쓰다가 교수 앞에서는 존댓말
1인칭으로 바뀐다. 스키마 주석이 이유를 못 박는다 — **「이 언어권에서 대명사는 사람이
아니라 관계쌍의 속성이다.」**

관계는 **추론하지 않고 사람이 선언**한다. 이유도 적혀 있다 — **「주소지정 추론기가
틀리면 조용히, 그리고 전체에서 틀린다.」**

### 갈래가 여럿 맞을 때 무엇이 이기는지 정해 뒀다

원문 하나에 기본값과 갈래 배열을 두고, 갈래마다 화자·청자·장면을 붙인다. 조회는
**화자 일치 100점 · 청자 50점 · 장면 25점**, 최고점이 이기고 동점이면 사용 횟수 →
최근 사용 → 삽입 순서로 가른다. 코드 주석 — **「조회는 결정적이다. AI도 퍼지 로직도 없다.」**

**우리 설계엔 이 규칙이 아예 없었다.** 갈래를 어떻게 담을지만 그리고 어느 것이 이기는지를
안 정했다. 안 정하면 나중에 코드가 마음대로 정한다.

### 저자의 실패담 — 이게 가장 값지다

- **「격은 화자의 문제가 아니라 맥락의 문제다.」** 화자 메타데이터만으로는 상대에 따라
  갈리는 대명사를 못 잡는다. 정규식 매트릭스가 서기 전에 **일회용 감사·수정 스크립트를
  스무 개 넘게** 먼저 썼다고 적었다.
- **손으로 쓴 대명사 규칙 문서가 가장 값진 산출물이었는데 어떤 도구도 그것을 읽을 수
  없었다.** 산문이라 프롬프트에 넣을 수도 검사에 쓸 수도 없어서, 규칙을 전부 QA 정규식으로
  다시 쓰고 세션마다 번역가에게 다시 설명해야 했다. 그게 관계쌍 맵을 만든 직접 동기다.
- 화자 정체성 규칙은 캐릭터별 금칙어로, 맥락 규칙은 별도 규칙 파일로 — 초기에 뭉뚱그린
  규칙을 남겨 뒀더니 이중 리포트가 됐다.

### QA 철학

**「오탐은 한 번 쳐다보면 끝이고, 미탐은 그대로 배포된다.」** 조용한 쪽이 아니라 시끄러운
쪽으로 튜닝하라는 것이다.

예시가 구체적이다. 태국어에서 「삼촌」을 화이트리스트에 넣었더니 「당신 나이는…」 안의
진짜 위반까지 함께 지워져 조용히 통과했다. 그래서 **길고 모호하지 않은 복합어만 예외로
넣고 짧고 모호한 것은 리포트가 늘어도 손으로 확인**한다. 규칙을 덜 걸리게 튜닝할 때마다
**이미 위반인 줄 아는 줄에 재실행해 여전히 걸리는지 확인**하는 절차가 있다.

### 우리가 안 보던 축

- **텍스트 종류** — 대사 · 지문 · 선택지 · 화면 · UI. 화자 무관 규칙이 UI까지 오적용되는
  것을 막는다.
- **혼잣말을 독립된 격으로** 취급한다. 캐릭터마다 독백용 1인칭을 따로 둔다.
- **별칭** — 한 인물이 여러 화자 코드로 나온다(등장 전엔 「???」). 캐노니컬 코드로 합치지
  않으면 같은 번역을 두 번 값 치른다.
- **좌표 안정성 계약** — 파일과 줄 번호를 메타데이터가 아니라 **맥락 창과 갈래 선택 양쪽의
  입력**으로 보고, 재추출해도 안 변해야 한다는 계약으로 못 박았다.

### 그 밖에 훔칠 것

- **프롬프트와 게이트를 한 소스에서 먹인다.** 페르소나 카드와 검사 규칙이 같은 레코드에서
  나온다. 프롬프트가 요구하는 목소리와 게이트가 검사하는 목소리가 갈리면 둘 다 무의미하다.
- **역방향 감사** — 새 규칙을 찾으면 같은 턴에 지침과 검사 규칙에 적고 전체를 재스캔한다.
  **게임 하나당 5~15회를 예산으로 미리 잡아 둔다.**
- **표본은 무작위로, 파일로.** 연속 표본은 화자별로 뭉치는 문제를 숨긴다. 채팅에 붙여넣지
  말고 파일로 넘긴다.
- 번역 착수 전에 **어느 경로로 번역할지 매번 사람에게 묻는다**(임의로 정하지 않는다).

## 우리 자리 — 무엇을 빌려 오고 무엇을 만드나

**빌려 온다** — 맥락 구분(`msgctxt`) · 정체성과 원문 분리 + 낡음 판정 · 좌표를 정체성으로 ·
번역 대상 제외 플래그 · 유래(provenance) · 근사치 플래그(fuzzy) · 작업 상태 축 ·
그림은 별도 테이블 · 갈래 선택 점수 규칙 · 사람 값이 기계 값을 이기는 우선순위.

**우리가 만든다** — **관계쌍 축 하나.** 조사한 게임 엔진 여섯 곳 어디에도 화자·말투가
1급 필드로 없다. 회사들은 이 문제를 만날 일이 없다. **원어로 쓰고 작가가 옆에 있으면
맥락이 이미 코드에 들어 있기 때문**이다. 이 문제는 경어가 있는 언어로 남의 게임을 작가
없이 번역할 때만 생기고, 그 처지에 놓인 사람은 실제로 같은 모양을 발명했다.

**아무도 안 하는 것 하나** — 정본에 **「이 값을 사람이 썼나 기계가 썼나」를 영구 필드로
남기는** 사례는 못 찾았다(조사자가 「찾아봤는데 없더라」로 구분해 보고). 표준(ITS)은
범주로 정의해 뒀는데 실제로 하는 사람이 없다. 우리 `fixlog`와 `Edit-Source` 꼬리표가
이미 그 일을 하고 있다.

## 한계

- 엔진 조사는 공식 문서를 못 가져온 자리가 많아 미확인 칸이 여럿이다. 「화자 메타가
  없다」는 조사자가 조사 범위 밖일 가능성을 명시했다.
- 관계쌍 사례는 **한 사람의 저장소 하나**다(1회 관측). 일반화하지 않는다.
- 표준 조사에서 「원문을 키로 쓰면서 맥락으로 가르는」 조합의 선례가 gettext 밖에는
  **못 찾았다**고 했지 없다고 하지 않았다.
