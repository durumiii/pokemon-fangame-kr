# 주연 대사 재번역 — 규모 재측정 (2026-08-06)

조사 전용. 정본은 한 줄도 건드리지 않았다. 이 문서 하나만 새로 썼다.

같은 날 쓴 [`2026-08-06-retranslate-scope.md`](2026-08-06-retranslate-scope.md)가
「사정권 8,440행」을 보고했는데, 유지자가 「전체 맵 대사 14,000행 정도인데 주연 대사만
9,000행이 넘는 게 말이 되느냐」고 지적했다. 지적이 옳다. 그 문서는 **단위가 다른 두 수를
같은 칸에 놓았다** — 8,440은 게임 안에서의 **등장 횟수**이고 14,000은 **번역 정본의 줄
수**다. 이 문서는 단위를 먼저 정의하고 규모를 다시 잰다.

세는 일은 전부 python으로 했다. grep 부분 문자열은 쓰지 않았다.

---

## 0. 한 줄 결론

「주연 대사 재번역」이 실제로 다시 쓰는 것은 **번역 정본 6,079줄**(화자가 확정된 전량
기준)이고, 화자 태그 156종 중 실제 주연 상위 30명으로 좁히면 **4,927줄**이다.
앞 조사의 8,440은 정본 줄이 아니라 등장 횟수였다.

## 1. 단위 넷 — 정의와 전체 실측

세는 단위가 넷이고, 넷이 서로 다른 질문에 답한다. 이 문서의 모든 표는 열 머리에 단위를
적는다.

| 단위 | 정의 | 답하는 질문 | 전체 값 |
|---|---|---|--:|
| **귀속표 행** | `speaker-attr.jsonl.gz`의 한 줄 = 이벤트 페이지 안 메시지 하나의 **등장 자리** | 「게임 안에서 몇 번 말하나」 | 19,310행 |
| **정본 행** | `translate/ko/00-maps.jsonl`의 `{k,v}` 한 줄 = **(맵, 원문) 하나** | 「고칠 줄이 몇 개인가」 | 13,770행 |
| **고유 원문** | 정본에서 원문(`k`)만 중복 제거 | 「서로 다른 스페인어 문장이 몇 개인가」 | 11,157개 |
| **고유 (원문,번역) 쌍** | 정본 줄에서 `(k, v)` 조합을 중복 제거 | 「서로 다른 한국어 문장을 몇 개 써야 하나」 | 11,516쌍 |

재현:

```sh
python3 -c "
import json,re,collections
fold=lambda s: re.sub(r'\s+',' ',s or '').strip()
c=[];cur=None
for l in open('translate/ko/00-maps.jsonl',encoding='utf-8'):
    r=json.loads(l)
    if 'map' in r: cur=r['map']; continue
    c.append((cur,fold(r['k']),r['v']))
print('정본 행',len(c),'· 고유 원문',len({k for _,k,_ in c}),
      '· 고유 쌍',len({(k,v) for _,k,v in c}),'· 맵 절',len({m for m,_,_ in c}))"
# → 정본 행 13770 · 고유 원문 11157 · 고유 쌍 11516 · 맵 절 475
```

### 1-1. 정본은 원문 하나에 한 줄이 아니다 — 맵마다 따로 갖는다 (실측)

이것이 규모 계산의 핵심이고, 앞 조사가 틀린 지점이다.

`00-maps.jsonl`은 절0(맵 대사)을 **맵 단위 해시 508개**로 담는다. 파일은
`{"map":N,"n":행수}` 머리줄과 그 맵의 `{k,v}` 줄들이 번갈아 오는 구조이며,
`build.py`가 맵마다 따로 dat 해시에 되쓴다(`translate/build.py:76-88`). 실측:

| 검사 | 값 |
|---|--:|
| 정본 행 | 13,770행 |
| 고유 `(맵, 원문)` | 13,770개 — **한 맵 안에서 원문은 유일하다** |
| 고유 원문 | 11,157개 |
| 차이(같은 원문이 다른 맵에도 있는 줄) | 2,613행 |
| 여러 맵에 걸친 원문 | 447개(총 3,060행) |
| 그중 맵마다 번역이 갈린 원문 | **305개**(총 1,717행) |

곧 **같은 원문이 맵마다 다른 한국어를 가질 수 있고, 실제로 305개가 그렇다.** 원장 미결
4번의 수치가 그대로 재현됐다(305개·1,717행). 편집 단위는 고유 원문이 아니라 정본 행이다.

재현:

```sh
python3 -c "
import json,re,collections
fold=lambda s: re.sub(r'\s+',' ',s or '').strip()
c=[];cur=None
for l in open('translate/ko/00-maps.jsonl',encoding='utf-8'):
    r=json.loads(l)
    if 'map' in r: cur=r['map']; continue
    c.append((cur,fold(r['k']),r['v']))
b=collections.defaultdict(set); n=collections.Counter()
for m,k,v in c: b[k].add(v); n[k]+=1
D={k for k in b if len(b[k])>1}
print('고유 (맵,원문)',len({(m,k) for m,k,_ in c}),'· 번역 갈린 원문',len(D),
      '· 그 정본행',sum(n[k] for k in D))"
# → 고유 (맵,원문) 13770 · 번역 갈린 원문 305 · 그 정본행 1717
```

### 1-2. 귀속표와 정본을 잇는 열쇠

귀속표 행은 이벤트 원문이라 줄바꿈을 그대로 담고, 정본의 `k`는 그 자리가 공백으로 접혀
있다. 공백류를 하나로 접는 열쇠(`re.sub(r'\s+',' ',k).strip()`)로 `(맵, 원문)`을 맞추면
귀속표 텍스트 행 17,081개 중 **17,070개(99.94%)**가 붙는다. 못 붙는 11행은 전부 빈
문자열이다. `speaker.py:199`의 `ko_key()`가 이미 이 열쇠를 쓴다(2026-08-06 수정분).

⚠ `build.py`의 `string_to_key`로 맞추면 15,800행만 붙는다(92.5%). 그 함수는 절23 같은
평문 절의 정규화를 재현한 것이고, 맵 대사에는 맞지 않는다 — 정본의 맵 대사 키
13,770개 중 **줄바꿈을 품은 것은 하나도 없다**(실측). 조인에는 공백 접기를 쓴다.

### 1-3. 귀속표가 정본을 얼마나 덮는가

| 항목 | 값 |
|---|--:|
| 정본 행 | 13,770행 |
| 귀속표가 닿는 정본 행 | 13,411행 (97.4%) |
| 안 닿는 정본 행 | 359행 |

안 닿는 359행은 표본을 보면 트레이너 승패 대사(「졌지만, 정말 자랑스러워!」 등)다.
맵 이벤트의 메시지 명령이 아니라 트레이너 데이터에 실려 있어 `speaker.py`의 스캔 범위
밖이다. 재번역 사정권과는 무관하다.

## 3. 중복 원문이 사정권에 미치는 영향 — 생각보다 작다

원장 미결 4번(「원문 11,157개 중 305개·1,717행이 여러 번역을 갖는다」)은 재검산에서
그대로 재현됐다. 다만 **그 중복의 대부분은 재번역 사정권 밖에 있다.**

| 항목 | 고유 원문 | 정본 행 |
|---|--:|--:|
| 정본 전체에서 번역이 갈린 원문 | 305 | 1,717 |
| 확정 사정권 안에서 2개 이상 정본 행을 갖는 원문 | 73 | 260 |
| 〃 (사정권 밖 맵의 같은 원문까지 포함) | 80 | 318 |
| 그중 **번역이 실제로 갈린** 것 | **40** | **80** |

번역이 갈린 40개를 화자로 갈라 보면:

| 갈래 | 고유 원문 |
|---|--:|
| 사정권 안 화자가 **한 명**뿐 | 40 |
| 사정권 안 화자가 **여럿** | 0 |

사정권 안에서 여러 정본 행을 갖는 73개 중 화자가 여럿인 것은 **7개**뿐이고, 그 7개는
번역이 갈리지 않았다(같은 한국어를 쓴다).

**함의**: 앞 조사 §2-8의 경고 — 「같은 원문이 여러 화자에게 쓰이는 자리(305개·1,717행)가
있어 재번역이 한 화자에 맞춰 갈면 다른 화자 자리가 깨진다」 — 는 **사정권 안에서는 거의
성립하지 않는다.** 그 305개·1,717행은 대부분 그림층(NPC 잡담)에 있다. 사정권에서 실제로
조심할 자리는 **7개 원문**이다. 문맥 없이 원문 키만 보고 고치지 말라는 원칙 자체는 옳지만,
그 근거로 305/1,717을 대는 것은 단위와 층을 함께 흐린다.

### 3-1. 키 단위로 고치면 51행이 더 딸려 온다

확정 사정권의 고유 원문 5,892개를 **키로** 정본에서 찾아 전부 고치면 **6,130 정본 행**이
닿는다. 화자가 실제로 확정된 정본 행은 6,079이므로 **51행이 여분**이다 — 같은 스페인어가
다른 맵에서는 화자 미확정(그림·미상·분기다름)으로 잡히는 자리다. 대개 「...」, 「하지만...」
같은 짧은 감탄·말줄임이다.

이 51이 앞 조사와 부모 재검산의 6,130과 이 문서의 6,079 사이 차이를 정확히 설명한다.

```sh
python3 -c "
import gzip,json,re,collections
fold=lambda s: re.sub(r'\s+',' ',s or '').strip()
c=[];cur=None
for l in open('translate/ko/00-maps.jsonl',encoding='utf-8'):
    r=json.loads(l)
    if 'map' in r: cur=r['map']; continue
    c.append((cur,fold(r['k']),r['v']))
CAN={(m,k):v for m,k,v in c}; K=collections.defaultdict(list)
for m,k,v in c: K[k].append(m)
rows=[json.loads(l) for l in gzip.open('docs/research/speaker-attr.jsonl.gz','rt',encoding='utf-8')]
C=[r for r in rows if r['how'] in ('태그','상속')]
ln={(r['map'],fold(r['k'])) for r in C if (r['map'],fold(r['k'])) in CAN}
ks={k for _,k in ln}
print('화자 귀속 정본행',len(ln),'· 키 단위 편집 시',sum(len(K[k]) for k in ks))"
# → 화자 귀속 정본행 6079 · 키 단위 편집 시 6130
```

## 6. 검산

| 검산 | 결과 |
|---|---|
| 정본 행 = 고유 (맵,원문) | 13,770 = 13,770 ✔ |
| 고유 원문 + 맵 중복분 = 정본 행 | 11,157 + 2,613 = 13,770 ✔ |
| 확정 정본 행 = 단일행 원문 + 다행 원문의 행 | 5,819 + 260 = 6,079 ✔ |
| 키 단위 편집 − 화자 귀속 = 사정권 밖 여분 | 6,130 − 6,079 = 51 ✔ |
| 화자별 귀속표 행의 합 = 확정 전량 | 8,440 = 8,440 ✔ |
| 화자별 **정본 행**의 합 vs 확정 전량 | 6,084 vs 6,079 — **5행 초과** |
| 화자별 **고유 원문**의 합 vs 확정 전량 | 5,920 vs 5,892 — **28개 초과** |
| 근거별 정본 행의 합 vs 귀속표가 닿는 정본 행 | 13,516 vs 13,411 — **105행 초과** |
| 귀속표 텍스트 행의 정본 조회 | 17,081 중 17,070 성공, 실패 11(전부 빈 문자열) |

새는 자리를 밝힌다. **귀속표 행은 화자별로 배타적이지만 정본 행은 아니다.** 같은 정본
줄이 여러 자리에 등장하면서 자리마다 다른 화자·다른 근거로 잡히면 양쪽에서 세어진다.
정본 행 5행·고유 원문 28개·근거별 105행의 초과가 전부 이 겹침이고, 위 §3의 「화자가
여럿인 원문 7개」와 같은 현상이다. 규모의 0.1% 수준이라 어느 안을 고르든 판단을 바꾸지
않지만, **화자별 표의 세로 합을 전체로 쓰면 안 된다.**

## 7. 한계 — 못 한 것, 불확실한 것

- **실기로 확인한 것이 하나도 없다.** 전부 데이터 판독이다.
- **귀속표 자체의 정확도는 다시 재지 않았다.** 이 문서는 `speaker.py`의 판정을 주어진
  것으로 놓고 규모만 셌다. 상속 3,705행의 화자가 맞는지는 별개 문제이며, `selftest`
  7자리 통과 외의 근거는 없다.
- **화자 태그 156종 판정은 사람 눈이다.** 156종을 실제 대사와 함께 하나씩 읽었으나,
  「사람인가 표지인가」는 최종적으로 판단이다. 퍼즐 화자 셋(`Lila`·`Naranja`·`Menta`)은
  판정을 보류했다. 다만 갈래를 어떻게 잡아도 흔들리는 폭은 정본 행 기준 **±10줄 안쪽**이다
  (갈래 A 전체가 정본 86행, 갈래 B가 120행).
- **ES 직함 접두 병합은 앞 조사의 목록을 그대로 썼다**(`Capitán`·`Capitana`·`Alcaide`·
  `Archidruida`·`Madame`·`Reina`). `Alto Caballero Tileo` · `Consejero Narciso` ·
  `Sacerdotisa Drácena` 같은 긴 직함형은 병합하지 않았다. 각 8·15·3 귀속표 행이라
  순위에는 영향이 없으나 「156종」이라는 종 수는 이만큼 부풀어 있다.
- **voices.md ↔ ES 태그 매핑도 앞 조사의 손 매핑(47태그)을 그대로 썼다.** 검증하지 않았다.
  「요리사」처럼 스프라이트로만 잡히는 항목은 여전히 이 집계 밖이다.
- **비용을 산정하지 않았다.** 글자 수는 냈으나 토큰이 아니고, 모델·프롬프트 오버헤드를
  곱하지 않았다. `docs/design/z-batch-run-proposal.md`의 실측 단가와 §4 표를 곱해야 한다.
- **재번역이 품질을 올린다는 것은 여전히 검증되지 않았다.** 이 문서는 규모만 잰다.
