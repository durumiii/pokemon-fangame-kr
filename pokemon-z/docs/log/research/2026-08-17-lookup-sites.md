# 문구 조회 지점 실측 (2026-08-17)

Z-73의 근거. 게임 설치본 `Scripts.rxdata`를 rubymarshal로 읽어 유효 절 233개를 전수로 셌다.

## 조회 함수 — 전부 원작 것이고 우리 모드가 아니다

절42 `Intl_Messages`에 있다.

| 함수 | 무엇으로 찾나 | 줄 |
|---|---|---|
| `MessageTypes.getFromHash(type, key)` | 전역 원문 해시 — 좌표 무관 | 687 · 563 |
| `MessageTypes.getFromMapHash(type, key)` | **현재 맵 → 맵0 → 원문** | 691 · 572 |
| `_INTL(*arg)` | `getFromHash` 래퍼 | 716 |
| `_MAPINTL(mapid, *arg)` | `getFromMapHash` 래퍼 | 751 |
| `_I(str)` | `_MAPINTL($game_map.map_id, str)` | 747 |

**맵 단위 좌표 조회는 이미 서 있다.** Z-73은 해상도를 맵에서 이벤트로 한 칸 내리는 일이지
메커니즘을 새로 만드는 일이 아니다.

## 부르는 자리

절53 `Messages`가 `Interpreter`와 `Game_Interpreter` **두 클래스**를 재정의하고, 양쪽에서
대사와 선택지를 그린다.

| 호출처 | 종류 | 넘기는 열쇠 | 줄 |
|---|---|---|---|
| `Interpreter#command_101` | 맵 대사 | `_MAPINTL($game_map.map_id, message)` | 634 |
| `Interpreter#command_102` | 선택지 | `getFromMapHash($game_map.map_id, c)` | 657 |
| `Game_Interpreter#command_101` | 맵 대사 | 같음 | 500 |
| `Game_Interpreter#command_102` | 선택지 | 같음 | 524 |
| `PMinigame_Duel` | 트레이너 전투 시작 대사 | `_I(...)` | 절161 |
| `SpriteWindow` | 가드 걸린 재정의(무효 추정, 미확인) | — | 절51 |

전수 카운트 — `_MAPINTL(` 7건 · `_I(` 7건(그중 5건은 절178 `Compiler`가 **코드 문자열을
만드는** 자리라 실행 호출이 아니다) · `getFromMapHash`/`getFromHash` 직접 호출 13건.
**맵 스코프 조회의 실질 실행 지점은 여섯 남짓.**

대조로 **전역 조회 `_INTL`은 5,116건**이다. 전투·메뉴·아이템 문구가 여기 있고 좌표 개념이
없다. 같은 원문이면 같은 번역이 맞는 자리라 손댈 대상이 아니다.

## 좌표를 얼마나 아는가

- `@map_id` — `setup()`에서 세팅된다. **다만 조회는 이것이 아니라 `$game_map.map_id`를 쓴다.**
- `@event_id` — 맵 이벤트는 세팅된다(`GameEvent.rb:263`). **공통 이벤트는 항상 0**
  (`GameCommonEvent.rb:75`가 0을 넘긴다 — 공통이벤트 ID 자체가 안 넘어간다).
- `@index` — 현재 명령 위치. 세팅되고 유지된다.
- **페이지 번호는 어디에도 없다.** `Game_Event`가 조건 맞는 페이지 객체만 들고
  (`GameEvent.rb:178-181`) 몇 번째인지는 저장하지 않으며, `setup()` 호출부 어디에도
  페이지 인덱스가 인자로 넘어가지 않는다(호출부 둘 다 확인). **부재의 명시적 확인이다.**

## 좌표를 못 구하는 경로

| 경로 | 아는 것 | 모르는 것 |
|---|---|---|
| 맵 이벤트 대사 | 맵 · 이벤트 · 명령 | 페이지 |
| 공통 이벤트 대사 | 실행 시점 맵 · 명령 | 이벤트ID(0) · 공통이벤트ID · 페이지 |
| 전투 문구 | 없음 | 전부 — `_INTL`만 쓴다 |
| 메뉴·UI | 없음 | 전부 |
| 트레이너 전투 시작 대사 | 실행 시점 맵 | 나머지 — 컴파일된 리터럴이라 원 좌표가 사라진다 |

## 이미 같은 자리를 수술했다

`share/patch_intl.py`(60~66행)가 `command_102` 양쪽에 `getFromMapHash` 호출을 얹는 수술을
이미 반영해 뒀다(선택지가 스페인어로 나가던 버그). **좌표 조회 수술은 같은 자리에 같은
방식으로 얹는 것이 된다.**

## 위험 (관측만)

- 같은 로직이 **두 클래스에 복제**돼 있다. 한쪽만 고치면 조용히 갈리고, **어느 쪽이 실제로
  도는지 코드로는 구분되지 않았다.**
- 조회가 이벤트 소속 맵이 아니라 실행 시점 맵을 쓴다. 갈리는 사례가 실제로 있는지 미확인.
- 공통 이벤트는 이벤트ID가 지워지므로 좌표 조회의 이점이 그쪽엔 안 먹는다.

## 「590묶음」 재측정 (2026-08-17)

이 수가 Z-53·Z-73 두 티켓에서 일의 크기를 재는 데 쓰였는데 **정의가 어긋나 있었다.**
정본과 귀속표를 직접 대조해 다시 쟀다.

| 무엇이 갈리는 묶음인가 | 수 |
|---|--:|
| 스프라이트 | **594** |
| 층(cls) | 219 |
| 배치 이름표(cast) | 197 |
| **화자(who)** | **153** (빈 값을 갈래로 치면 196) |
| 귀속법(how) | 102 |
| 트레이너 클래스 | 6 |

정본 묶음은 13,807개이고 자리가 둘 이상인 것이 2,660개다(옛 기록의 13,417·2,606과
근소한 차이 — 그 뒤 정본이 늘었다).

**옛 「화자가 갈리는 590묶음」은 실은 스프라이트 기준 594였다.** 스프라이트가 다른 것은
화자가 다른 것이 아니다 — 같은 인물의 다른 모습일 수도, 한쪽이 배경 물체일 수도 있다.

그리고 153도 상한이다. 표본을 보면 상당수가 **같은 역할의 남녀 쌍**이라 갈릴 이유가 없다.

```
맵4  · '¿Eso es un \v[66]? …'  · campesinaw / nina
맵7  · '¡Uf, puf! …'            · campesinaw / campesinow   (농부 여/남)
맵20 · 'Has elegido... ¡bien!'  · Mosquetera / Mosquetero    (총사 여/남)
```

재현 — `translate/ko/00-maps.jsonl`의 (맵, 원문)을 묶음으로 잡고
`translate/data/speaker-attr.jsonl.gz`를 (map, k)로 조인해 칸별 고유값이 둘 이상인 묶음을
센다.
