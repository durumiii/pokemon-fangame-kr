# 절23 죽은 키 전수 — 미번역 1,519/2,031 중 진짜 일감을 가른다 (2026-08-18)

Z-53 검사 게이트의 「남은 몫」(죽은 키 가르기)을 채우는 조사. 정본·게임·게이트 코드는
건드리지 않았다 — 관측만 담는다.

## 재료와 방법

전수 캐기를 새로 돌리지 않고 **선행 실측의 원시 데이터를 그대로 재사용했다** —
`docs/log/research/2026-08-17-sec23-overlap-raw.jsonl`(Scripts.rxdata 전 섹션에서
`_INTL("..."/'...')` 첫 인자 리터럴을 정규식으로 뽑고 루비 이스케이프를 푼 것, 5,112개
호출 자리, 필드 `si`(섹션 id)·`name`(섹션 이름)·`ln`(줄)·`lit`(리터럴)). 재사용이 맞는지는
먼저 옛 수치(죽은 키 3,530/51.5%)를 다시 내서 확인했다 — 아래에서 정확히 재현됐다.

```
python3 - <<'PY'
import json, re
raw = [json.loads(l) for l in open("docs/log/research/2026-08-17-sec23-overlap-raw.jsonl")]
def string_to_key(s):   # build.py/gate.py와 동일 함수
    if re.search(r"[\r\n\t\x01]|(?m:^\s+|\s+$)|\s{2,}", s):
        s = re.sub(r"(?m)^\s+", "", s); s = re.sub(r"(?m)\s+$", "", s)
        s = re.sub(r"\s{2,}", " ", s)
    return s
calls = {}
for r in raw:
    k = string_to_key(r["lit"]); calls[k] = calls.get(k, 0) + 1
canon = [json.loads(l) for l in open("translate/ko/23-script-texts.jsonl")]
# 판정: canon 각 행의 정규화 키가 calls에 있으면 산 키, 없으면 죽은 키
PY
```

정규화는 `translate/build.py`·`translate/stage0/gate.py`의 `string_to_key`와 글자 그대로
같은 함수를 썼다(두 곳 다 이 규칙: `\r\n\t\x01`나 앞뒤 공백·연속 공백이 있으면 앞뒤 자르고
내부 연속 공백을 하나로 접는다). 대조 대상은 정본 `translate/ko/23-script-texts.jsonl`
(6,849행, `k` 중복 0). 죽은/산 키 판정 뒤, 게이트의 미번역 두 기준(text-pipeline.md 「미번역을
셀 때는 기준을 함께 적어라」)을 **정본 자체에서 직접 재계산**해 교차했다 — stage0
`findings/untranslated.jsonl`을 거치지 않고 `v==k`(기준①)·`re.search(r"[가-힣]", v)` 없음
(기준②)을 canon 행에 바로 적용했다(gate.py `check_untr`과 동일 로직, 절23은 `apply=="global"`
이라 `src`가 곧 `k`).

재현: `python3 <이 문서 위 블록>` 또는 산출 파일
`docs/log/research/2026-08-18-sec23-dead-keys.jsonl`을 직접 읽으면 행마다 `calls`·`alive`·
`값=원문`·`한글무포함`·`cls`(비번역 사유 분류, 아래 참고)가 있다.

## 결과 3 — 「산 키이면서 미번역」 167/195건을 열어 보니 전량 번역 대상이 아니었다

산 키(호출 1회 이상)이면서 값이 원문과 같은 167건을 전부 열어 사유를 분류했다
(재현: `docs/log/research/2026-08-18-sec23-dead-keys.jsonl`에서 `alive==true and 값=원문==true`
인 행의 `cls`). 분류 기준(guide text-pipeline.md 「키 이름·마크업 전용·자산 이름은 번역하면
안 되는 부류」를 그대로 적용, 각 사유는 실제 호출 섹션을 확인해 정함):

| 분류 | 수 | 판정 근거 |
|---|---|---|
| `key` — 키보드/조작키 이름 | 84 | `A`~`Z` 단일 문자, `F1`~`F24`, `Numpad 0`~`9`, `Ctrl`/`Alt`/`Esc`/`Enter`/`Home`, 숫자 낱개, `;:` 등 부호. 전부 `Controles`(조작 설정) 섹션 — text-pipeline.md 「번역값이 해시 키로 쓰이는 자리」와 같은 위험군이라 **번역하면 항목이 깨진다** |
| `asset` — 그림/파일 경로 | 29 | `Graphics/Pictures/...`, `pokedexbg`, `pokedexSearchbg` — 자산 이름 |
| `markup-template` | 23 | `{1}`, `{1} {2}`, `<ac><c2=...>{1}</c2></ac>`, `x{1}` 등 자리표시자·서식 태그뿐, 번역할 글자가 없음 |
| `markup-template(PP/HP)` | 5 | `PP: {1}/{2}` 류 — `PP`/`HP`는 포켓몬 게임의 관용 약자(공식 한국어판도 그대로 씀)라 원문 유지가 맞는 값 |
| `debug` | 11 | `BattleAnimationEditor`·`Compiler`·`Controles`·`Pokedex Mejorada`(개발용 커스텀 폼 라벨) 섹션 — 플레이어가 안 보는 개발 도구 문자열 (실 사용처: `BattleAnimationEditor:2046` 등, raw jsonl로 확인) |
| `pokedex-alpha-group` | 9 | `ABC`~`YZ` — 도감 검색 화면의 영문 알파벳 그룹 라벨(`PScreen_Pokedex:571` 등). 한글 자모 그룹 개념이 없어 원문 유지가 맞음 |

| `unit-template` | 3 | `????.? lbs.`/`m`/`kg` — 도감 몸무게·키 단위, 숫자는 자리표시자고 단위 기호만 남아 번역 대상 없음 |

**기준②의 추가 28건(195−167)도 확인했다** — 값이 원문과 다르면서 한글이 없는 행 전부가
`Nv.→Lv.`(레벨 약자 스페인어→영어 관용 표기 교체), `PS→HP`, `<<`→`←`, `Bloq Mayus`→`Caps
Lock`처럼 **이미 번역(변환)이 끝난 값**이었다 — 결과물이 한글이 아닐 뿐 미번역이 아니다.

**진짜 일감(산 키 AND 미번역, 기준① 또는 ②) = 0건.** 절23 키 단위에서는 실제로 손댈 자리가
없다. **확정도: 실측**(167건 전량 표본 확인, 자동 분류가 아니라 전량 사유를 실 호출처와
대조해 확정 — `docs/log/research/2026-08-18-sec23-dead-keys.jsonl` `cls` 필드).

## 결과 4 — 역방향(스크립트에는 있는데 정본에 없는 키)

고유 호출 키 3,320개 중 정본에 없는 것은 **1개**(`'|'`, `Controles` 섹션에서 2회 호출 —
조작키 표시의 구분 문자, `A|B` 같은 표시에 쓰는 부호). 마크업/부호 전용이라 번역 대상이
아니다. **필터링 후 진짜 누락 = 0건.**

선행 조사(`2026-08-17-sec23-overlap.md` §5)와 **정확히 일치**한다(그쪽도 "'|' 1건,
Controles 절, 조작키 구분자 2곳"으로 적었다). **확정도: 실측.**

## 결론 — Z-53에 등재할 수치

- 절23 미번역 1,519행(기준①) / 2,031행(기준②) 중 **죽은 키(호출 0건)가 각각 1,352 /
  1,836행**이고, 방치가 맞다(text-pipeline.md 판정과 일치).
- **산 키이면서 미번역인 167 / 195행은 전량 비번역 대상**(조작키 24종·자산명·마크업
  서식·개발 도구 문자열·도감 알파벳 그룹·PP/HP/VS 관용 표기)이었다 — **절23 키 단위의
  진짜 번역 일감은 0건.**
- 역방향(스크립트에 있는데 정본에 없는 키)도 필터링 후 0건.
- **따라서 절23은 「미번역 1,519/2,031행」이라는 수치와 무관하게, 키 단위로는 사람이
  더 번역할 자리가 남아 있지 않다.** 지침 text-pipeline.md의 「미번역이 남았다는 방향을
  거꾸로 잡기 쉽다」 경고가 절23 전체에 그대로 들어맞는다.

## 한계

- 선행 조사가 이미 지적한 대로 전수 재추출과 4~10건 오차가 날 수 있는 문형(정규식이
  여러 줄 리터럴이나 `+` 연결을 놓치는 경우)이 있다 — raw jsonl을 그대로 재사용했으므로
  이번 조사도 같은 한계를 그대로 물려받는다(자릿수 판단에는 영향 없음, 선행 조사 §1).
  **이번 조사에서 새로 도는 재추출은 하지 않았다** — 그 재추출 자체가 다음 수라면 남아 있다.
- 비번역 분류(167건)는 사람이 실 호출처(raw jsonl의 `si`/`name`/`ln`)를 확인해 정한
  것이라 실측이지만, 분류 규칙(예: `markup-template` 판정의 정규식)은 이번 조사에서 새로
  짠 것이라 경계 사례가 있을 수 있다 — 167건 전량을 열어 확인했으므로 누락 가능성은
  낮다(추정: 사유 오분류가 있어도 「번역 대상 아님」이라는 결론 자체는 바뀌지 않는다,
  개별 사유 라벨만 흔들릴 수 있다).
- 절23 밖(다른 절, 맵 대사 절00 등)은 이번 조사 범위가 아니다.
- 게이트 산출(`translate/stage0/findings/untranslated.jsonl`)과의 직접 대조는 하지
  않았다 — 대신 같은 로직을 정본에서 독립적으로 재계산해 합계가 일치하는 것으로
  간접 검증했다(결과 2).
