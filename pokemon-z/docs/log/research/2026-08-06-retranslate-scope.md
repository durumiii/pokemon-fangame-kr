**그림 5,088행을 빼는 근거는 「이미 했다」이다.** 2026-08-02의 NPC 배치

정리하면 **재번역 사정권은 「태그 + 상속」 8,440행에서 비인물 태그 294행을 뺀
8,146행이 상한**이고, 그 밖의 층은 각자 다른 처방을 갖는다.

### 1-7. 번역 조회는 사실상 100% 된다 — 다만 조인에 함정이 있다

확정 8,440행의 고유 원문 5,892개는 **전부** `translate/ko/00-maps.jsonl`에 번역이 있다.

⚠ 그런데 귀속표의 `k`를 그대로 열쇠로 쓰면 **343개(5.8%)가 조회에 실패한다.** 원인은
줄바꿈이다. 귀속표는 이벤트 원문의 `\n`을 그대로 담고, `00-maps.jsonl`의 `k`는 그
자리가 공백으로 접혀 있다. `build.py`의 `string_to_key`(게임의 정규화 재현)는 이
차이를 메우지 못한다 — 루비의 `\s+$`는 줄 끝 앵커라 앞에 공백이 없는 `\n`은 남긴다.
공백을 하나로 접는 `re.sub(r'\s+',' ',k).strip()`으로 재조회하면 343개 중 342개가
붙고, 남는 1개는 빈 문자열이다.

**`speaker.py`의 `ko_index()`(`translate/speaker.py:199-208`)가 `k.strip()`을 열쇠로
쓰므로 같은 구멍을 갖는다.** `lines`·`who`가 이 5.8%에서 번역 대신 원문을 보여준다.
재번역 파이프라인은 조인 열쇠를 먼저 고쳐야 한다.

재현:

```sh
python3 -c "
import gzip,json,re
rows=[json.loads(l) for l in gzip.open('docs/research/speaker-attr.jsonl.gz','rt',encoding='utf-8')]
ko={}
for l in open('translate/ko/00-maps.jsonl',encoding='utf-8'):
    r=json.loads(l)
    if 'map' not in r: ko.setdefault(r['k'].strip(), r['v'])
conf=[r for r in rows if r['how'] in ('태그','상속')]
miss={r['k'].strip() for r in conf if r['k'].strip() not in ko}
ko2={re.sub(r'\s+',' ',k).strip() for k in ko}
print('원시 미스', len(miss), '· 줄바꿈 포함', sum(1 for k in miss if chr(10) in k),
      '· 공백 접기 후 미스', sum(1 for k in miss if re.sub(r'\s+',' ',k).strip() not in ko2))"
# → 원시 미스 343 · 줄바꿈 포함 334 · 공백 접기 후 미스 1
```

## 2. 되돌릴 수 있게 하는 장치 — 무엇이 쓸려 나가는가

### 2-1. 원문 키별 마지막 커밋

`translate/ko/00-maps.jsonl`을 만진 커밋은 52개(머지 제외 47개)다. 각 커밋의 diff에서
추가된 jsonl 줄의 `k`를 뽑아, 새 커밋부터 읽으며 처음 만난 커밋을 「그 원문을 마지막으로
손댄 커밋」으로 잡았다. 원문 **11,157개** 전량에 커밋이 붙었다.

재현(그대로 붙여 넣으면 된다):

```sh
git log --no-merges --format='%H' -p --unified=0 -- translate/ko/00-maps.jsonl | python3 -c "
import sys,json,re,collections
last={};sha=None
for l in sys.stdin:
    l=l.rstrip(chr(10))
    if re.fullmatch(r'[0-9a-f]{40}',l): sha=l; continue
    if not l.startswith('+') or l.startswith('+++'): continue
    b=l[1:].strip()
    if not b.startswith('{'): continue
    try: r=json.loads(b)
    except Exception: continue
    if 'k' in r: last.setdefault(re.sub(r'\s+',' ',r['k']).strip(), sha[:8])
print(len(last), collections.Counter(last.values()).most_common(4))"
# → 11157 [('c88666e7', 5418), ('f9d93f31', 3699), ('f8d300d3', 459), ('356e28c9', 180)]
```

### 2-7. 되돌릴 장치 — 설계안 셋

#### 설계 1. 보호 목록 파일

`translate/protected.jsonl`(원문 키 + 근거 커밋 + 사유)을 두고, 재번역 적용기가 이
목록의 키를 건너뛴다. 목록은 §2-1 명령으로 생성한다.

- 비용: 생성 스크립트 30줄 안팎 + 적용기의 `if key in protected: continue` 한 줄.
- 한계: 보호는 곧 **옛 번역 고착**이다. 범위를 잘못 잡으면(867 전량) 재번역이 사정권의
  15%를 못 만진다. 또 목록은 「그때 그 판정이 지금도 옳다」를 전제한다 — 뱃사공 어투가
  한 번 물려진 이력(`f0c0425`→`6ab61a4`)이 그 전제가 늘 참은 아님을 보인다.

#### 설계 2. 나란히 놓고 고르는 검토 단계

재번역 산출을 `translate/ko/00-maps.cand.jsonl` 후보 파일로 두고, `fixgui.py`에 옛/새
좌우 비교 화면과 채택 버튼을 얹는다.

- 비용: fixgui에 화면 하나 + 후보 파일 로더. 기존 저장 이력·되돌리기를 그대로 쓴다.
  대략 150~250줄.
- 한계: **검토가 병목이다.** 사정권을 가장 좁게 잡아도(상위 5명) 고유 원문 2,948개다.
  한 줄에 10초를 쓴다 해도 8시간이 넘는다. 이 화면은 「전수 검토」가 아니라 「걸린
  자리만 검토」로 쓸 때만 값이 있다.

#### 설계 3. 브랜치 분리 + 행 단위 채택

워크트리에서 통째로 재번역하고, `git diff`를 읽어 채택할 줄만 골라 담는다.

- 비용: **0.** 새 도구가 필요 없다. 워크트리 규율은 이미 이 저장소의 관행이다.
- 한계: diff가 수천 줄이면 사람이 훑는 것은 설계 2와 같은 병목이고, 부분 채택이
  손작업이다. 단, 「전수 검토를 안 한다」고 정하면 이 한계는 사라진다 — 되돌리는
  단위가 커밋이어도 되기 때문이다.

### 2-8. 권하는 안 — 설계 3을 뼈대로, 설계 1을 좁게 얹는다

**설계 2는 만들지 않는다.**

1. **재번역은 워크트리 브랜치에서 돈다.** 되돌리기 장치는 git이다. 새 도구 없음.
2. **자동 제외 목록은 어투·화자 판정 182개(252행) 하나뿐이다.** 유지자 판정이 실린
   문장은 기계가 다시 쓰지 않는다. 목록 생성은 §2-1 명령 그대로.
3. **용어 치환 685개는 제외하지 않고 재번역한다.** 회귀는 `verify.py`가 잡는다.
   못 잡는 갈래(프랑스어 호칭·배지·별명·capitán·지명)는 **`names.jsonl` 등재를 늘려**
   기계 검사로 옮긴다 — 사람 검토보다 싸고, 어차피 다음 판에도 다시 필요하다.
4. **사람이 보는 것은 전수가 아니라 세 목록이다.** ① 보호 목록에 걸려 건너뛴 자리
   ② `verify.py` FAIL ③ 어미 급 검사(조사본 §2 후보 C, `register.py`)의 잔존.
   이 셋만 보면 검토가 수천에서 수백으로 떨어진다.

이유는 하나다. **비용이 가장 낮은 장치가 이미 저장소에 다 있다** — git은 되돌리기를,
`verify.py`는 용어 회귀를, 어미 검사는 어투 회귀를 각각 맡는다. 새로 만들 것은
목록 파일 하나뿐이고, 그것도 §2-1 명령의 출력을 파일로 떨구는 일이다.

⚠ 이 권고에 붙는 조건: **재번역 적용은 반드시 원문 키가 아니라 `(맵,이벤트,페이지)`
문맥과 함께 검토돼야 한다.** 같은 원문이 여러 화자에게 쓰이는 자리(원장 미결 4번,
305개·1,717행)가 있어, 재번역이 한 화자에 맞춰 문장을 갈면 다른 화자 자리가 깨진다.

```sh
python3 -c "
import gzip,json,collections,statistics as st
rows=[json.loads(l) for l in gzip.open('docs/research/speaker-attr.jsonl.gz','rt',encoding='utf-8')]
p=collections.defaultdict(list)
for r in rows: p[(r['map'],r['event'],r['page'])].append(r)
sel=[k for k,v in p.items() if any(x['how'] in ('태그','상속') for x in v)]
s=sorted(len(p[k]) for k in sel)
print(len(sel),'페이지 ·',sum(s),'행 · 중앙값',st.median(s),'· 최대',max(s),

```

### 3-3. 등장인물 명단을 프롬프트에 줄 수 있는가 — 줄 수 있다

귀속표에 `cast` 칸이 이미 있다. 페이지 안의 이름표 인물 목록이다(`speaker.py:129`).
다만 그림으로 잡히는 화자는 `cast`에 없으므로, 명단은 `cast`가 아니라 **그 페이지의
`who` 유니크 집합**으로 만들어야 한다.

명단에 말투를 실을 수 있는지가 관건이다.

| 항목 | 값 |
|---|--:|
| 확정 페이지 835 중 화자 전원이 voices.md 등재 | **522 (63%)** |
| 나머지 | 313 (37%) |

37%의 페이지에는 말투가 정해지지 않은 화자가 하나 이상 있다. §1-3의 명단
(Ginia 120행 · Loto 89행 · Eneldo 32 …)이 그 대부분이다.
**재번역 착수 전에 voices.md에 이들을 얹는 것이 선결 과제**이며, 안 얹은 채 돌리면
그 페이지들은 배치가 말투를 스스로 지어낸다.

재현:

    if r['how'] in ('태그','상속'): p[(r['map'],r['event'],r['page'])].add(n(r['who']))
print(len(p),'페이지 · 전원 등재',sum(1 for w in p.values() if w<=V))"
