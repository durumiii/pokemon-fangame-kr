# Z-49 — Controller UX 엑스박스판 (유저 「키 변경」 흡수)

발단: 디시 갤러리 유저의 「키 변경」(2026-08-11 배포) — 조작을 패드 배열로 옮기는 모드.
우리 `Controller UX`와 같은 자리를 건드려 그대로는 못 얹는다.

## 무엇을

유저 모드의 **목적**을 흡수하되 방식은 다시 짠다. 만드는 것은 범용판이 아니라
**엑스박스 패드 기준판**이다.

- **화면 단위 입력 치환기** — 유저가 복사한 세 파일(대사 출력 310줄 · 가방 149줄 ·
  일시정지 메뉴 324줄)에서 **실제로 바뀐 코드는 도합 10줄**이고 전부 「이 화면에서
  어떤 가상 버튼을 읽나」다. 화면 진입점을 별칭으로 감싸 그 구간에서만 버튼을 갈아
  읽게 하면 546줄 복사가 사라진다. 중첩되므로(메뉴에서 가방을 연다) 스택으로 만들고
  `ensure`로 반드시 꺼낸다.
- **필드 입력은 이벤트 훅으로** — `Events.onMapUpdate`가 입력 분기 바로 앞에서 돈다.
  거기서 `menu_calling`·`keyItemCalling`·`runtoggle`을 세우면 원본이 이어받는다.
  `Scene_Map#update` 통째 재정의를 피하는 것이 이 티켓의 핵심 — 그 함수를 별칭으로
  잡는 자리가 원작에 다섯(따라다니는 포켓몬 포함), 우리 모드에 넷 더 있다.
  ⚠ 훅은 더하기만 된다. 원본 배정을 없애야 하는 배치는 택하지 않는다.
- **배속에서 L 빼기** — 원작 `TurboNuevo`의 `Input.update`에서 조건 한 줄만 다르다.
  통째 재정의 대신 **로드 순서**로 푼다(L 제거판을 커서 숨김보다 앞 번호로).
- **패드 없으면 비활성** — `Input.joystick`이 `nil`이면 라벨 치환을 통째로 건너뛴다.
  지금 `004_PadLabels.rb`가 패드 유무를 안 보고 무조건 발동하는 것이 실제 결함이고,
  유저가 그 파일을 통째로 끈 이유다.
- **가방 그림 16장** — 유저 사본을 그대로 넣는다(`replaces_crc`는 한글패치 코어판 CRC).
  생성 스크립트는 두지 않는다 — 게임 업데이트가 끝나 코어 자산이 바뀔 일이 없다(유지자 판정).

## 하지 않는 것

- **권장 F1 배치표를 문서로 내지 않는다.** 모드 안내문(`mod.json` 설명)에만 적는다.
- **`%APPDATA%`의 배치 파일을 설치기가 쓰지 않는다** — 남이 F1에서 만든 배치를 덮는다.

## 배선 기준 — 실행기 **기본 F1 배치**다 (유지자 판정 2026-08-13)

이 기계의 표는 기본값에서 확인·취소만 엑스박스 관례로 바꾼 **특이 사례**다. 모드는
그걸 전제하지 않고 **손대지 않은 기본 배치**를 기준으로 배선한다. 라벨은 **엑스박스
물리 이름**으로 적는다.

기본 배치를 엑스박스 패드에 대면 이렇다(`Game.exe`의 SDL 매핑 DB 실측 —
`XInput Controller,a:b0,b:b1,x:b2,y:b3,leftshoulder:b4,rightshoulder:b5,
leftstick:b8,rightstick:b9,guide:b10`):

| 가상 | 원시 번호 | 엑스박스 물리 |
|---|---|---|
| B(취소) | JS0 | **A**(아래) |
| C(확인) | JS1 | **B**(오른쪽) |
| X | JS2 | X(왼쪽) |
| A(달리기) | JS3 | Y(위) |
| Y | JS4 | **LB** |
| Z | JS5 | **RB** |
| L | JS9 | 오른쪽 스틱 클릭 |
| R | JS10 | 가이드 버튼 |

**확인·취소는 모드가 입력층에서 맞바꾼다** (유지자 판정 2026-08-13). 기본값에서는
확인이 B(오른쪽), 취소가 A(아래)라 엑스박스 관례와 반대인데, F1을 고치라고 안내하는
대신 **가상 B와 가상 C의 판독을 서로 바꾼다** — 유저 모드의 `CtoAChanger.rb`가 쓰는
방식이고(A↔C), 우리는 기본 배치라 B↔C가 된다. 그러면 손대지 않은 F1에서 아래 버튼이
확인, 오른쪽 버튼이 취소가 된다.

⚠ **키보드도 같이 바뀐다.** 실행기는 가상 버튼이 키보드에서 왔는지 패드에서 왔는지
알려 주지 않는다(`Input.press?`는 출처를 안 싣는다 — mkxp-z 확장에도 그 구분이 없다).
그래서 **패드가 붙어 있을 때만**(`Input.joystick`이 nil이 아닐 때) 맞바꾸고, 안내문에
「패드를 꽂은 채 키보드로 하면 확인·취소가 뒤바뀐다」를 적는다.

⚠ **가상 L·R은 쓰지 않는다** — 엑스박스에서 오른쪽 스틱 클릭과 가이드 버튼에 떨어지고,
가이드는 OS·스팀이 가로챈다.

## 알아 둘 것 — 배치는 모드가 못 바꾼다

물리 버튼과 가상 버튼의 짝은 실행기 F1 메뉴가 정하고 게임 폴더 밖
(`%APPDATA%\<제목>\keybindings.mkxp1`)에 저장된다. 모드는 읽지도 쓰지도 못한다.
유저 모드가 가상 Y·L·R을 쓰고 라벨을 「Y·L·R」로 적은 것은 **가상 이름과 물리 이름이
맞게 F1을 다시 잡은 사람의 배치**다 — 그대로 재현하지 않는다. 위 「배선 기준」 절이
우리가 잡을 기준이다.

패드 종류(`Input.joystick[:name]`)는 **라벨 표기에만** 쓴다. 구판은 원시 버튼 번호로만
묶어서 종류를 알아도 배치를 못 고친다.
