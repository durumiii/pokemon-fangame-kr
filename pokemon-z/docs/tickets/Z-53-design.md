# Z-53 설계 — 0단계 정본의 모양

티켓 본문([Z-53](Z-53.md))은 무엇을 할 것인가, 이 문서는 어떤 모양이어야 하는가.
그림은 [Z-53-design.d2](Z-53-design.d2). **승인 전 설계안이다** — 판정거리는 7절.

## 1. 푸는 문제

**값이 어디 있는지가 흩어져 있어 검사도 흩어져 붙고, 안 붙은 자리로 값이 샌다.**
지난 두 주의 결함이 전부 이 한 문장이었다. 검증이 24절 중 여덟만 봐서 트레이너 클래스에
스페인어가 남았고, 층을 스프라이트로 추론해 인물 대사 130여 행이 지문으로 잡혔고,
코퍼스 대조가 원문 완전 일치에만 걸려 687행이 사각에 들었다.

유지자 원칙 — **「번역의 핵심은 SoT다. 하드코딩 목록이 존재하는 것 자체가 문제다」**
(2026-08-13) · **「복잡도의 원천을 줄여 간단하게 만드는 게 중요하지 파일 크기가 작아지는
게 중요하지 않다」**(2026-08-14).

## 2. 지금 모양 (실측 2026-08-17)

### 절 24개가 한 꼴이 아니다

| 꼴 | 절 | 레코드 | 정합 검사 |
|---|---|---|---|
| 번호로 서는 리스트 | 01~13 · 18 · 21 | `{"i", "v"}` (12·13·18은 `es` 병기) | **개수만.** `build.py:128-134`가 길이만 보고 `i`가 가리키는 자리에 쓴다 — 번호가 밀려도 통과 |
| 원문 키로 서는 해시 | 00 · 14 · 19 · 20 · 22 · 23 | `{"k", "v"}` | **키 문자열.** `build.py:118·148`이 위치별로 대조하고 어긋나면 죽는다 |

티켓이 의심하던 「번호가 밀려도 조용히 통과한다」를 코드로 확인했다. **절의 절반이
스스로를 못 지킨다.**

맵 절(14,315행)만 머리줄 `{"map","n"}`이 따로 있고, 508개 전부 `n`이 실제 줄 수와 맞는다.
전투 대사 절 셋(15~17)은 0행이다 — 그 대사는 이벤트에 들어 있다.

### 판정 메타가 이미 아홉 파일

`divergence-allowed`(46) · `unified-phrases`(434) · `frozen-keys`(54) · `protected`(1,768) ·
`approved-lines`(999) · `approved-events`(448) · `register-ok`(11) · `z4-excluded`(98) ·
`term-pairs`(57).

**`divergence-allowed`가 0단계 레코드의 원형이다** — 원문 하나, 갈래 여럿, 갈래마다 값과
적용 자리와 사유. 나머지 여덟은 그 한 레코드의 다른 칸이다.

### 귀속은 정본 밖에서 추론된다

`speaker.py scan`이 게임 원본에서 `speaker-attr.jsonl.gz`(19,834행)를 만든다.
층은 PS 9,132 · PC 6,388 · N 4,314. 귀속법은 그림 5,088 · 태그 4,735 · 상속 3,705 ·
선택지 2,229 · 미상 1,759 · 지문 1,124 · 분기다름 562 · 전투호출 522 · 명단1 108 ·
스크립트 2.

층은 「그림이 사람인가」와 「이름표가 사람 이름인가」 두 신호로 **추론한 값**이고,
정본은 이 표를 원문 문자열로 조인해서만 만난다.

### 값의 출처와 반영 경로는 다른 축이다

출처 스무 갈래는 [전수표](../log/research/2026-08-17-names-outside-translation-table.md)와
[하드코딩 조사](../log/research/2026-08-14-sot-hardcode-survey.md)에 있다. 설계가 반드시
갈라야 할 것은 이 둘이다.

- 이벤트가 만드는 트레이너 이름 495개는 **조회를 탄다** — 절14에 키만 얹으면 된다.
- 배틀시설 트레이너 875명은 **조회를 안 탄다** — 코드 수술이 먼저다.
- PBS는 **출처이면서 고쳐서는 안 되는 자리**다. 손대면 `Data/`의 dat 21개가 원본에서
  다시 만들어진다.
- 무슈·마담·마드모아젤은 용어쌍 정본과 `batch_pages.py` 상수와 프롬프트 문서에 **세 벌**.

## 3. 모양 — 표 셋

하나로 뭉치면 판정이 자리마다 복제되고, 자리마다 나누면 조건이 복제된다.
**이름을 붙여 셋으로 가르면 둘 다 사라진다.**

셋을 「대장」이라 부르지 않는다 — 이 저장소에서 대장은 `docs/ledger/`의 판정층 이름이라
데이터 파일에 쓰면 두 축이 한 말이 된다([용어](../../../docs/terms.md)).

### 자리표 — 문자열 하나가 있는 곳

지금 `speaker-attr`이 담는 것에 **출처 종류와 반영 경로가 칸으로 더해진다.**

```
{ "자리": {"kind":"map", "map":288, "event":12, "page":0, "cmd":3},
  "es": "¿Has averiguado algo, \\PN?",
  "출처": "rxdata",     // rxdata · pbs · code · gamedata · script-table · picture
  "반영": "조회",        // 조회 · 소스수술 · 그림 · 손댈수없음
  "층": "PS", "화자": "크리산토", "청자": "주인공", "군": ["칼로스기사단"] }
```

번호로 서던 절도 같은 꼴이다 — `{"kind":"sec", "sec":13, "i":121}`이 `es`를 함께 들므로
**번호만으로 쓰는 일이 없어진다.**

### 값표 — 원문 하나에 갈래 여럿

**갈래가 하나면 그게 통일이다.** 통일 목록·갈림 허용 목록·승인 줄이 한 레코드의 칸이 된다.

```
{ "es": "¡Hasta la próxima!",
  "갈래": [ {"ko":"다음에 또 보자!",     "군":"평대NPC", "왜":"…", "유래":"batch/2026-08-03"},
            {"ko":"다음에 또 뵙겠습니다!", "군":"존대NPC", "왜":"…", "유래":"human/2026-08-16"} ] }
```

`유래` 칸이 `fixlog.jsonl`과 `Edit-Source` 꼬리표가 따로 하던 일을 대신한다.

### 대상군표 — 조건에 붙인 이름

**조건은 대상군에 이름을 붙여 한 번만 정의하고, 축별 판정이 그 이름에 붙는다.**
말투 대장 97항과 페르소나표 110항이 이미 이 꼴이라 만드는 것이 아니라 옮기는 것이다.

```
{ "군": "아조스단신병", "조건": {"tclass": [42, 43]},
  "말투": "조무래기 구어", "판정근거": "ledger/voices.md#아조스단" }
```

규칙은 400~500개로 어림된다(이름표 327종 · 스프라이트 321종). **규칙이 못 덮은 행이
남은 일감이고, 그 목록이 빌드 산출물 하나다.**

## 4. 사라지는 것과 남는 것

| 지금 결함 | 0단계가 서면 |
|---|---|
| 번호 밀림이 조용히 통과(`build.py:128`) | 자리가 `es`를 들어 번호만으로 쓰지 않는다 |
| 검사가 24절 중 8절에만(`verify.py`) | 자리마다 오라클을 선언하고 게이트가 한 번 돈다 |
| 미번역을 한 번에 못 봄 | `ko == es`인 자리를 한 질의로 센다 |
| 층 오배정(Z-55·Z-67) | 층이 추론이 아니라 자리표의 칸 |
| 분기다름 203행이 배치에서 빠짐(Z-58) | 귀속법이 칸이라 게이트가 조건으로 선다 |
| 격 검사기가 청자를 안 봄(Z-66) | 청자가 칸으로 선다 |
| 같은 번역쌍이 세 곳에 복제 | 값표 한 곳 |
| 판정 메타 아홉 파일 | 한 레코드의 칸들 |

**남는 것** — 본가 코퍼스 대조(`canon_sweep.py`의 세대 채택)는 「본가 자구가 무엇인가」를
푸는 별개 문제다. 낡은 스냅숏 가드는 배치 파이프라인의 기계다. 오라클이 없는 절(맵 대사·
음차 이름·창작 지명)은 **설계가 사람 몫으로 인정해야 한다** — 못 보는 것을 못 본다고
적는 것이 게이트의 일부다.

## 5. 이행 — 읽기 전용 파생물부터

유지자 판정(2026-08-17).

1. 표 셋을 지금 출처에서 **기계로만** 만든다. 사람 판정은 받지 않고 지금 값을 옮긴다.
2. 표 셋에서 번역표 24절을 빌드해 지금 정본과 대조한다. **목표는 차이 0.**
3. 차이가 0이 된 뒤 주도권을 넘긴다 — 정본이 표 셋이 되고 번역표는 산출물로 내려간다.
4. 그 다음 삼킨 여섯을 푼다([Z-53](Z-53.md) 「삼킨 자리」).

**2단계의 대조가 이 설계의 채점표다.** 차이 나는 자리를 세지 않고 넘어가면 0단계도 같은
병을 물려받는다.

## 6. 안 하는 것

- **게임 비의존 일반화** — 재사용은 Z를 끝낸 뒤 별도 단계다. 두 번째 게임을 잡을 때 요구를 준다.
- **PBS 수정** — 출처로 읽기만 한다.
- **씬 축 정교화** — 정밀도 0.89~0.94로 가를 수 있으나 그 구분이 번역 처방을 안 바꾼다
  (Z-57·Z-59 닫음 기록).

## 7. 판정거리

1. **자리 좌표를 무엇으로 삼나.** 맵 대사는 (맵,이벤트,페이지,명령), 번호 절은 (절,인덱스).
   한 칸에 두 꼴을 담을지, 꼴을 칸으로 가를지.
2. **(맵, 원문)마다 한 줄이라 한 맵 안에서 자리별로 다른 값을 못 주는 제약**을 어떻게 표현하나.
   묶음 13,807개 중 2,660개가 자리 둘 이상이고 그중 **153~196묶음**이 화자가 갈린다
   (옛 「590」은 스프라이트 기준 594였다 — 2026-08-17 재측정). 조회 방식이
   그런 것이라 표현해도 빌드가 소스 수술로 넘겨야 한다.
3. **규칙 400~500개라는 어림이 맞나.** 재 봐야 하는 수다(P-1).
4. **파일 꼴.** JSONL로 갈지 사람이 고치기 더 좋은 꼴로 갈지. 「사람이 읽을 수 있어야
   한다」는 요구가 여기 걸린다.

## 확정도

2절의 수치와 코드 줄은 실측이다(조사 서브 셋의 보고를 파일·코드로 대조). **3절은 설계안이고
아직 아무것도 만들지 않았다.** 4절의 「사라진다」는 설계가 그대로 설 때의 이야기다.

한계 — `names.json`이 396행인데 8월 14일 하드코딩 조사의 내역 합과 맞지 않는다. 어느 쪽이
최신인지 안 갈랐다. 인명을 값표로 옮기기 전에 대조해야 한다.
