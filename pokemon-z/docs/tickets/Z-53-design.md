# Z-53 설계 — 0단계 정본은 어떤 모양인가

티켓 본문([Z-53](Z-53.md))이 「무엇을 할 것인가」라면 이 문서는 「어떤 모양이어야 하는가」다.
그림은 [Z-53-design.d2](Z-53-design.d2)에 있다.

⚠ **이 문서는 아직 승인 전 설계안이다.** 여기 적힌 모양으로 무엇을 만들지는 유지자
판정을 받고 정한다. 「열린 물음」 절이 그 판정거리다.

## 1. 무엇을 푸는가

한 문장으로 — **값이 어디 사는지가 흩어져 있어서 검사도 흩어져 붙고, 그래서 안 붙은
자리로 값이 샌다.** 지난 두 주 동안 잡은 결함이 전부 이 한 문장의 다른 얼굴이었다.
검증이 24절 중 여덟만 보아 트레이너 클래스에 스페인어가 그대로 남아 있던 것, 층 판정이
스프라이트를 추론해서 인물 대사 130여 행이 지문으로 잡힌 것, 코퍼스 대조가 원문 완전
일치에만 걸려 687행이 사각에 들어간 것이 그렇다.

유지자 원칙(2026-08-13): **「번역의 핵심은 SoT다. 하드코딩 목록이 존재하는 것 자체가
문제다.」** 그리고 (2026-08-14): **「복잡도의 원천을 줄이고 통일시켜 간단하게 만드는 게
중요하지 파일 크기가 작아지는 게 중요하지 않다.」**

## 2. 지금 모양 (실측 2026-08-17)

### 번역표 24절은 한 가지 꼴이 아니다

| 꼴 | 절 | 레코드 | 정합을 무엇으로 보나 |
|---|---|---|---|
| 번호로 서는 리스트 | 01~13 · 18 · 21 | `{"i": 인덱스, "v": 한국어}` (12·13·18은 `es` 병기) | **개수만.** `build.py:128-134`가 `len(rows)==len(obj)`만 보고 `i`가 가리키는 자리에 곧바로 쓴다 — 번호가 밀려도 조용히 통과한다 |
| 원문 키로 서는 해시 | 00 · 14 · 19 · 20 · 22 · 23 | `{"k": 원문, "v": 한국어}` | **키 문자열.** `build.py:118·148`이 위치별로 키를 대조하고 어긋나면 죽는다 |

맵 절(`00-maps.jsonl`, 14,315행)만 머리줄이 따로 있다 — `{"map": 번호, "n": 줄수}` 뒤에
그 맵의 레코드가 `n`개 이어진다. 맵 섹션 508개 전부에서 `n`이 실제 줄 수와 맞는다(전수 대조).
절15~17(전투 시작·승리·패배 대사)은 **0행이다** — 그 대사는 절이 아니라 이벤트에 산다.

**「번호가 밀려도 조용히 통과한다」는 티켓의 주장은 코드로 확인했다**(`build.py:128-134`).
같은 결함이 해시형 절에는 없다. 즉 지금 정본은 절의 절반이 스스로를 못 지킨다.

### 판정과 메타는 이미 아홉 파일로 흩어져 있다

| 파일 | 줄 | 담는 것 |
|---|--:|---|
| `data/divergence-allowed.jsonl` | 46 | 원문 하나에 갈래 여럿 — `{es, 이유, 갈래[]{ko, maps[], sprites[]}, src}` |
| `data/unified-phrases.jsonl` | 434 | 여러 맵에 흩어진 같은 원문의 통일값 |
| `data/frozen-keys.jsonl` | 54 | 배치에 다시 태우면 안 되는 자리 |
| `data/protected.jsonl` | 1,768 | 보호 좌표 (맵·이벤트·페이지) |
| `data/approved-lines.jsonl` | 999 | 검수 승인된 대사 |
| `data/approved-events.jsonl` | 448 | 검수 승인된 이벤트 |
| `data/register-ok.jsonl` | 11 | 격 전환이 의도인 예외 |
| `data/z4-excluded.jsonl` | 98 | 재번역 제외 |
| `term-pairs.jsonl` | 57 | 용어쌍 |

**`divergence-allowed.jsonl`이 0단계 레코드의 원형이다.** 원문 하나 · 갈래 여럿 · 갈래마다
값과 적용 자리와 사유. 위 아홉은 그 한 레코드의 서로 다른 칸이지 서로 다른 개념이 아니다.

### 귀속은 정본 밖에서 추론된다

`speaker.py scan`이 게임 원본을 읽어 `data/speaker-attr.jsonl.gz`(19,834행)를 만든다.
층은 PS 9,132 · PC 6,388 · N 4,314, 귀속법은 그림 5,088 · 태그 4,735 · 상속 3,705 ·
선택지 2,229 · 미상 1,759 · 지문 1,124 · 분기다름 562 · 전투호출 522 · 명단1 108 ·
스크립트 2다. **층은 「그림이 사람인가」와 「이름표가 사람 이름인가」 두 신호로 추론한
값이고, 정본은 이 표를 원문 문자열로 조인해서만 만난다.**

### 값이 사는 자리는 번역표 밖이 더 넓다

출처 스무 갈래가 [전수표](../log/research/2026-08-17-names-outside-translation-table.md)와
[하드코딩 조사](../log/research/2026-08-14-sot-hardcode-survey.md)에 있다. 설계가 반드시
갈라야 할 것은 **「값의 출처」와 「반영 경로」가 다르다**는 점이다.

- 이벤트가 만드는 트레이너 이름 495개는 **조회를 탄다** — 절14에 키만 얹으면 닿는다.
- 배틀시설 트레이너 875명은 **조회를 아예 안 탄다** — 코드 수술이 먼저다.
- PBS는 **출처이면서 고쳐서는 안 되는 자리**다. 손대면 재컴파일이 걸려 `Data/`의 dat
  21개가 원본에서 다시 구워진다.
- 무슈·마담·마드모아젤 세 쌍은 용어쌍 정본과 `batch_pages.py` 상수와 프롬프트 문서에
  **각각 한 벌씩 세 곳**에 산다.

## 3. 0단계의 모양 — 대장 셋

한 파일이 아니라 셋이다. 하나로 뭉치면 판정이 자리마다 복제되고, 자리마다 나누면
조건이 복제된다. **이름을 붙여 셋으로 가르면 둘 다 사라진다.**

### 자리 대장 — 문자열 하나가 사는 곳

한 줄이 게임 안의 한 자리다. 지금 `speaker-attr`이 담는 것에 **출처 종류와 반영 경로가
칸으로 더해진다.**

```
{ "자리": {"kind":"map", "map":288, "event":12, "page":0, "cmd":3},
  "es": "¿Has averiguado algo, \\PN?",
  "출처": "rxdata",              // rxdata · pbs · code · gamedata · script-table · picture
  "반영": "조회",                // 조회 · 소스수술 · 그림 · 손댈수없음
  "층": "PS", "화자": "크리산토", "청자": "주인공", "군": ["칼로스기사단"] }
```

번호로 서던 절도 같은 꼴로 선다 — `{"kind":"sec", "sec":13, "i":121}`에 `es`가 함께
있으므로 **번호만으로 쓰는 일이 없어진다.**

### 값 대장 — 원문 하나에 갈래 여럿

`divergence-allowed`를 모든 원문으로 넓힌 것이다. **갈래가 하나면 그게 통일이고, 지금의
통일 목록·갈림 허용 목록·승인 줄은 이 한 레코드의 다른 칸이 된다.**

```
{ "es": "¡Hasta la próxima!",
  "갈래": [ {"ko":"다음에 또 보자!", "군":"평대NPC", "왜":"...", "유래":"batch/2026-08-03"},
            {"ko":"다음에 또 뵙겠습니다!", "군":"존대NPC", "왜":"...", "유래":"human/2026-08-16"} ] }
```

`유래` 칸이 지금 `fixlog.jsonl`과 `Edit-Source` 꼬리표가 따로 하던 일을 대신한다.

### 군 대장 — 조건에 붙인 이름

**조건은 대상군에 이름을 붙여 한 번만 정의하고, 축별 판정이 그 이름에 붙는다.** 말투
대장 97항과 페르소나표 110항이 이미 이것이므로 새로 만드는 것이 아니라 옮기는 것이다.

```
{ "군": "아조스단신병", "조건": {"tclass": [42, 43]},
  "말투": "조무래기 구어", "판정근거": "ledger/voices.md#아조스단" }
```

규칙은 400~500개 근처로 어림된다(이름표 327종 · 스프라이트 321종). **규칙이 못 덮은
행이 곧 남은 일감이고, 그것이 빌드의 산출물 하나다.**

## 4. 무엇이 사라지나

| 지금 결함 | 0단계가 서면 |
|---|---|
| 리스트형 절의 번호 밀림이 조용히 통과(`build.py:128`) | 자리가 `es`를 들고 있어 번호만으로 쓰지 않는다 |
| 검사가 24절 중 8절에만 붙음(`verify.py`) | 자리마다 오라클을 선언하고 게이트가 한 번 돈다 |
| 미번역을 한 번에 못 봄 | `ko == es`인 자리를 한 질의로 센다 |
| 층 오배정(Z-55·Z-67) | 층이 추론이 아니라 자리 대장의 칸이 된다 |
| 분기다름 203행이 배치에서 빠짐(Z-58) | 귀속법이 칸이므로 게이트가 조건으로 선다 |
| 격 검사기가 청자를 안 봄(Z-66) | 청자가 칸으로 선다 |
| 같은 번역쌍이 세 곳에 복제 | 값 대장 한 곳 |
| 판정 메타가 아홉 파일 | 한 레코드의 칸들 |

**사라지지 않는 것도 적어 둔다.** 본가 코퍼스 대조(`canon_sweep.py`의 세대 채택 규칙)는
「본가 자구가 무엇인가」를 푸는 별개 문제라 그대로 남는다. 낡은 스냅숏 가드도 배치
파이프라인의 기계라 남는다. 오라클이 아예 없는 절(맵 대사·음차 이름·창작 지명)은
**설계가 그것을 인정하고 사람 몫으로 남겨야 한다** — 못 보는 것을 못 본다고 적는 것이
검사 게이트의 일부다.

## 5. 이행 — 읽기 전용 파생물부터

유지자 판정(2026-08-17): **읽기 전용 파생물로 먼저 세워 대조한 뒤 주도권을 넘긴다.**

1. **대장 셋을 지금 출처에서 기계로 만든다.** 이 단계에서 사람 판정은 하나도 안 받는다 —
   지금 값을 그대로 옮기기만 한다.
2. **대장에서 번역표 24절을 빌드해 지금 정본과 값을 대조한다.** 목표는 차이 0이다.
   차이가 나면 그 자리가 곧 지금 정본이 스스로를 못 지키던 자리다.
3. 차이가 0이 된 뒤에 **주도권을 넘긴다** — 정본은 대장이 되고 번역표는 산출물로 내려간다.
4. 그 다음에야 삼킨 여섯을 푼다([Z-53](Z-53.md) 「삼킨 자리」).

**2단계의 대조 결과가 이 설계의 채점표다.** 대조가 안 맞는 자리를 세지 않고 넘어가면
0단계도 지금과 같은 병을 물려받는다.

## 6. 안 하는 것

- **게임 비의존 일반화를 지금 넣지 않는다.** 다른 팬게임 재사용은 Z를 끝낸 뒤 별도
  단계다(유지자 판정 2026-08-17). 두 번째 게임을 실제로 잡을 때 그 요구를 준다.
- **PBS를 고치지 않는다.** 출처로 읽기만 한다.
- **씬 축을 정교하게 만들지 않는다.** 정밀도 0.89~0.94로 가를 수는 있으나 그 구분이
  번역 처방을 안 바꾼다(Z-57·Z-59 닫음 기록).

## 7. 열린 물음 — 판정거리

1. **자리 대장의 좌표를 무엇으로 삼나.** 맵 대사는 (맵,이벤트,페이지,명령)이고 번호로
   서는 절은 (절,인덱스)다. 한 칸에 두 꼴을 담을지, 꼴을 칸으로 갈지.
2. **(맵, 원문)마다 한 줄이라 한 맵 안에서 자리별로 다른 값을 못 주는 제약**을 0단계가
   어떻게 표현하나. 묶음 13,417개 중 2,606개가 자리 둘 이상이고 그중 590묶음은 화자가
   갈린다. 조회 방식이 그런 것이라 표현은 해도 빌드가 소스 수술로 넘겨야 한다.
3. **군 대장의 규칙이 400~500개라는 어림이 맞나.** 이건 재 봐야 하는 수다(P-1).
4. **파일 꼴을 무엇으로 하나.** 지금처럼 JSONL로 갈지, 사람이 읽고 고치기 좋은 다른
   꼴로 갈지. 「사람이 읽을 수 있어야 한다」는 요구가 여기 걸린다.

## 확정도

2절의 수치와 코드 줄 번호는 전부 실측이다(2026-08-17, 조사 서브 셋의 보고를 파일과
코드로 대조). 3절의 레코드 꼴은 **설계안이며 아직 아무것도 만들지 않았다.** 4절의
「사라진다」는 설계가 그대로 서면 그렇다는 것이지 실측이 아니다.

한계 하나 — `names.json`이 396행인데 8월 14일 하드코딩 조사가 적은 내역의 합과 맞지
않는다. 어느 쪽이 최신인지 대조하지 않았다. 인명을 대장으로 옮길 때 먼저 갈라야 한다.
