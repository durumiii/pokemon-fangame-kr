# Z-54 — 재번역 파이프라인 안전판 셋 (P-3, 중간)

Z-47 라운드에서 실측된 결함 세 갈래의 구조 수선. 근거:
[유실 감사](../log/research/2026-08-13-human-edit-loss-audit.md) ·
[라운드 경위](../log/research/2026-08-13-z47-round-triage.md).

1. **plan이 (맵, 접힌 원문) 단위로 접지 않는다** — 같은 정본 자리를 화자별로 중복
   배치해 열쇠 충돌 23건·버려질 번역을 만들었다. 공유 열쇠는 한 번만, 화자가 갈리면
   「양쪽에 서는 격」 지시를 달아 보낸다.
2. **apply_verdicts 안전판에 fixlog가 없다** — 스튜디오 손수정 64자리가 무판정
   기본값에 덮였다. provenance(fixlog + Edit-Source 커밋)를 안전판에 넣는다.
3. **낡은 산출 스냅숏 가드가 없다** — 산출 파일의 old가 현행 정본과 다르면 그 행은
   반영 전에 멈추고 알린다(검수 세트 문맥 행이 옛 값을 재반영한 사고 — 하루 3회).
**2번의 자국이 지금도 남아 있다 (실측 2026-08-16).** `fixlog.jsonl`이 손댄
`00-maps.jsonl` 줄마다 유지자의 **마지막 `new`**를 현재 정본과 대조하면 어긋나는 줄이
있다 — 행 단위 기록(`kind=row`) 531줄 기준 **34줄**(조사원은 다른 거름으로 649줄 중
71줄을 셌다. 어느 거름이 맞는지는 안 맞춰 봤다).

확인된 자국 하나: 줄 7448(망각의 감옥 간수)을 2026-08-09 유지자 스튜디오 수정이
`잊었어?` → `잊었나?`로 확정했는데, 2026-08-13 Z-47 배치 커밋(`50e2f9e`)이 `잊었냐?`로
되돌렸다. 이 줄은 복원했다.

⚠ **34줄 전부가 덮인 것은 아니다.** 그중 여럿은 그 뒤의 유지자 판정이다 — 「고고트라이드를
사용하시겠습니까?」→「사용할까?」는 2026-08-16 시스템 지문 통일 판정의 결과다. 줄마다
가려야 하고, **대조 자체를 도구로 만들어 두는 것이 이 티켓의 몫**이다.

4. **(추가 2026-08-13, fixnotes 미라 건) 보호의 이벤트 확산이 재번역·선별을 통째로
   가린다** — provenance가 손수정 한 줄(맵79 호칭 어순 1행)을 이벤트 페이지 전체
   보호로 넓혀, 손 안 탄 존대 오역 3행이 배치 풀·선별에 아예 안 들어갔다(맵79
   이벤트 19~22, plan/chunks·산출·verdicts 전부 부재 실측). 보호 확산은 유지하되
   「보호로 빠진 페이지 수」를 plan이 찍고, 격 검사 같은 정적 검진은 보호와 무관하게
   돌 길을 둔다.

5. **(추가 2026-08-18, 실증) `provenance.py build` 재작성이 보호 219페이지를
   지운다** — 현행 protected.jsonl(1,768페이지)과 build 재생성본(1,746페이지)을
   대조하니 재생성에서 사라지는 페이지 219, 그중 승인 이벤트로도 안 가려지는
   **실제 노출이 209페이지**다(스크래치 재생성 실측, 정본 파일은 건드리지 않았다).
   `apply_verdicts.lock_pages`는 append하는데 build는 전체 재작성이라 두 생산자가
   충돌하고, 지침(retranslation 「배치를 돌리기 전에 다시 만든다」)을 따르는 순간이
   방아쇠다. **수리됐다(2026-08-18, 유지자 판정 ⓑ)** — 원인은 마지막 커밋만 보는
   모델이었다: 사람 낱건 뒤에 온 기계 일괄(45행 값 수리 2b1451b가 191페이지, 표기
   통일 2d1cf14 등)이 마지막 손이 되며 이전 human 흔적을 지웠다. walk가 사람 낱건을
   이력 전체에서 **누적**하도록 고쳤고, 재생성 대조 유실 0 · 순증 309페이지(지워졌던
   낱건 복원). build는 행 단위 출처 목록 `data/provenance-lines.jsonl`(6,029행)도 함께
   내고 stage0 gen이 그것을 값의 state·by로 흡수한다 — 페이지 목록은 이제 그 목록의
   파생이다. 남은 결함: from_reports가 제보의 자리(`맵:순번`)를 **현재** 정본 줄
   순서로 푼다 — 줄이 늘거나 줄면 옛 제보가 딴 줄을 가리킨다(미실측, 코드 판독).
