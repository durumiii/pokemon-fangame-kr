# Z-31 — 모바일 실행기에서 굵은 한글 그리기가 튕긴다 (v5.2.1)

제보: [2026-08-08 디시 스레드](../log/reports/2026-08-08-runa-boldhangul-crash.md).
Runa(아이폰)와 RPG Player 둘 다, 난이도 선택창 진입 시 튕김. RPG Player가 띄운 오류가
원인을 그대로 가리켰다:

    Script 'DPPT Font/003_BoldHangul.rb' line 38: ArgumentError occurred.
    comparison of String with 192 failed

## 원인 (실측 — 재현 완료)

`pixelShadowWide?`의 바이트 판독이 「`getbyte` 있으면 그걸, 없으면 `s[0]`」 이분법이었다.
1.8.7(s[0]=Fixnum)과 정식 1.9+(getbyte 있음)만 가정한 것인데, 이들 모바일 실행기는
**1.9 의미론(`s[0]`이 String)이면서 `String#getbyte`가 없다** — 그래서 String과 192의
비교가 되어 ArgumentError.

- 재현: 루비 3.4.5에서 `String#getbyte`를 undef하고 배포 코어(v5.2.1
  `share/dist/…_2-dppt.zip`의 `Data/Scripts.rxdata`에서 추출한 003 섹션과 레포 현행이
  동일함을 확인)의 함수를 실행 → 같은 문구의 ArgumentError.
- 증상과 정합: `pixelShadowWide?`는 **굵은 글자를 그릴 때만** 불린다(`ch[6]`가 참일 때
  단락 평가). 인트로·성별·이름(굵기 없음)은 멀쩡하고 첫 굵은 한글이 나오는 난이도
  선택에서 튕긴 관측과 일치.

## 수리 (정본 반영됨, 배포 대기)

`mods/DPPT Font/003_BoldHangul.rb` — 폴백을 `s[0]`에서 `s.unpack("C")[0]`으로.
getbyte가 있으면 그대로 쓰고(정식 루비 전부), 없을 때만 unpack이라 어느 쪽에서도
바이트 그대로다. unpack은 이미 코어에 구워져 도는 `josa.rb`(`unpack("C*")`)와 같은
관용구. 루비 3.4에서 두 갈래(getbyte 유·무) 모두 가/é=true, A/공백=false 확인.

**남은 일** — 이 스크립트는 합본 셋의 코어(Scripts.rxdata)와 글꼴 모드 zip에 구워져
나간다. 코어 재굽기 + 재배포가 있어야 유저에게 닿는다(릴리스는 유지자 승인).

## 같은 제보의 다른 관찰 (미판정)

- **루나에서 몬스터볼을 던지면 오류창, 볼이 소모만 되고 안 던져진다** — 제보자 본인이
  003을 손수 고친 판이라 「제 수정 탓일 수도」라고 유보. 우리 쪽 재현·원인 미확인.
  2026-08-09 정적 감사([호환 감사](../log/research/2026-08-09-ruby-compat-sweep.md))로
  던지기 경로를 훑었다 — fgetb는 each_byte 기반이라 안전, josa는 rescue 전면 포장이라
  크래시 불가. **유력 후보는 `Array#nitems`(1.9에서 제거)** — Runa는 mkxp-z 기반
  (루비 3.1이 기본, App Store 명시)이고, 볼 사용 허가 검사(`PItem_ItemEffects`의
  CanUseInBattle)가 `party.length>=6 && $PokemonStorage.full?`, 그 `full?`
  (PScreen_Storage)가 nitems를 부른다. **파티 6마리일 때만** 걸려 초반 무증상과
  들어맞는다. 확인 질문 둘: 오류가 날 때 파티가 꽉 찼었는지 · RPG Player 쪽
  오류창 문구(화면). 파티 5마리 이하에서 볼이 잘 던져지면 이 가설이 산다.
  맞으면 수리는 Z-32의 호환 심 한 줄(nitems 복원)이다.
- **루나에서 Controller UX 모드가 안 먹힌다**(RPG Player에선 먹힘) — 남의 모드 +
  실행기 차이. 우리 작업 범위인지부터 판정 필요.
- Runa는 같은 오류에서 대화창 없이 즉사한다 — 제보 유도 시 RPG Player 쪽 화면을
  부탁하는 편이 진단에 낫다.
