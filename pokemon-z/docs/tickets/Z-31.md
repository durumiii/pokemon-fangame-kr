# Z-31 — 모바일 실행기(신형 루비) 호환 묶음

구 Z-31(굵은 한글 튕김)과 구 Z-32(신형 루비 지뢰 선제 제거)를 합쳤다(2026-08-09) —
같은 재배포에 실리는 한 묶음이다. 발단 제보:
[2026-08-08 디시 스레드](../log/reports/2026-08-08-runa-boldhangul-crash.md),
지뢰 목록: [2026-08-09 호환 감사](../log/research/2026-08-09-ruby-compat-sweep.md),
현행 규칙: [packaging](../guides/packaging.md)의 「신형 루비 실행기 호환」 절.

## 정본 반영 완료, 재배포 대기

**① 굵은 한글 튕김 수리** — Runa·RPG Player가 난이도 선택창(첫 굵은 한글)에서
`comparison of String with 192 failed`(003_BoldHangul.rb 38줄)로 튕겼다. 원인은
`pixelShadowWide?`의 바이트 판독 폴백 `s[0]` — 문자열 첨자가 1.9 의미론이면서
`getbyte`가 없는 실행기(RPG Player 실측)에서 String 대 정수 비교가 된다. 폴백을
`unpack("C")[0]`으로 바꿨고(`mods/DPPT Font/003_BoldHangul.rb`), 루비 3.4에서
getbyte 유·무 두 갈래 모두 가/é=true, A/공백=false로 판정 동일 확인. 재현은
`getbyte`를 undef한 3.4에서 배포 코어의 실물 섹션으로 같은 문구를 얻어 확정했고,
릴리스 자산=로컬 dist(sha256 일치) 확인으로 「옛 판이 나갔다」 가설은 기각.

**② 신형 루비 호환 층** — 코어 맨 앞 심 섹션 「Z-32 Ruby Compat」(없는 API만 채움:
`nitems`·`Thread.critical`·`File/Dir.exists?`·`Fixnum`/`Bignum`·`getbyte`) + 1.8 전용
구문 수술(AudioUtilities `when N:` 콜론 23곳 → `when N then`, PScreen_Load rescue 밖
`retry` 1곳 → `next`; `loop do` 블록 안이라 1.8에서도 관측 동작 동일). 소스 정본
`share/ruby-compat.rb`, 반영 도구 `share/patch_ruby_compat.py`(멱등). 보관소 기반판·
PC 설치본 양쪽 적용 완료 — 3.4.5 재감사 문법 불통 0, 비수술 258섹션 소스 무손상,
심 기능 실행 검증(getbyte 없는 흉내 런타임 포함).

**코어 재굽기·글꼴 모드 재조립 완료(2026-08-09)** — 보관소의 「한글패치 코어」를
재조립했고(번역표 새로 굽기 포함, Z-24 치환·호환 심이 코어에 실림), 글꼴 모드 셋도
다시 지었다(굵은 한글 수리 + Z-21 갈무리 라틴 이식이 실림). 네 모드 modkit lint
오류 0. 재조립 도중 잡은 지뢰 둘(제자리 rmtree·비멱등 빌드)은 도구에서 수리했다.

**모드 릴리스 mods-z-v3 나감(2026-08-09)** — PC 실기 확인 통과 후 모드 채널로 배포.
**남은 것** — 합본 zip(`share/make_package.py --variant runa --font <갈래> --zip`)과
합본 릴리스(유지자 승인 대기).

## 로컬 mkxp-z 시험대 (P-2, 다음 수)

Runa의 속은 mkxp-z(루비 3.1)고 mkxp-z는 데스크탑 빌드가 공개돼 있다. Windows용
mkxp-z 신판에 패치 적용본을 얹으면 iOS 없이 Runa와 거의 같은 런타임으로 인트로·볼
던지기·박스 화면을 직접 밟아볼 수 있다 — 정적 감사가 못 보는 「조용한 오판형」(비교가
거짓이 돼 기능만 어긋나는 부류)과 타입 미상 첨자까지 잡는 그물. 한계: Runa 포트만의
손질(iOS 입출력·섹션 오류 처리)은 재현 못 한다.

## 미판정 관찰 (같은 제보에서)

- **루나에서 몬스터볼을 던지면 오류창, 볼이 안 던져진다** — 던지기 경로 정적 훑기로
  fgetb(each_byte 기반)·josa(rescue 전면 포장)는 무혐의. **유력 후보는
  `Array#nitems`** — 볼 사용 허가 검사(`PItem_ItemEffects`의 CanUseInBattle)가
  `party.length>=6 && $PokemonStorage.full?`이고 그 `full?`(PScreen_Storage)가
  nitems를 부른다. **파티 6마리일 때만** 걸려 초반 무증상과 들어맞고, 위 심이 이미
  덮는다. 확인 질문 둘: 오류 때 파티가 꽉 찼었는지 · RPG Player 쪽 오류창 문구(화면).
  파티 5마리 이하에서 볼이 잘 던져지면 이 가설이 산다.
- **루나에서 Controller UX 모드가 안 먹힌다**(RPG Player에선 먹힘) — 남의 모드 +
  실행기 차이. 우리 작업 범위인지부터 판정 필요.
- Runa는 오류에서 대화창 없이 즉사한다 — 제보 유도 시 RPG Player 쪽 화면을
  부탁하는 편이 진단에 낫다.
