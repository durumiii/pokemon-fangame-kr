# Z-69 — 검증이 절 절반을 안 본다

**단계** P-3 · **크기** 중간

`verify.py`가 절을 지정해 보는 곳은 24절 중 여덟(00·01·02·05·07·10·12·23)뿐이고, **검사가
하나도 안 걸리는 절이 열셋**이다(03·04·06·08·09·11·13·14·18·19·20·21·22. 절15~17은 정본·dat
양쪽이 0줄이라 셈에서 뺐다). 오늘 절13이 화면에 원문으로 뜨는지 조사하다 우연히 걸어 들어간
자리이고, 크기를 재니 절반이었다. 실측은
[커버리지 조사](../log/research/2026-08-17-verify-coverage.md).

**빌드가 이미 막는 것은 뺀다.** 해시 절은 `build.py`가 줄 수와 자리별 키 문자열을 대조해
골격 사고가 빌드에서 죽는다. **리스트 절은 길이 하나만 본다** — `i`가 중복·누락돼도, 게임
판이 올라 인덱스 뜻이 밀려도 조용히 통과한다. 진짜 구멍은 여기다.

## 이미 새고 있는 것 (오늘 실측)

- **절13 i=121이 `{"i": 121, "v": "Papa"}`** — 스페인어가 한국어 칸에 그대로 있다. 두 겹으로
  안 걸렸다: 절13에 검사가 없고, `messages.dat`의 절13[121]이 비어 있어 「값 = 원문」 검사로도
  못 잡는다. `PBS/trainertypes.txt`를 오라클로 써야 잡힌다.
- **절14에 원문 그대로인 값 여덟** — `AZ`는 정본 표기라 의도이고, `Ejemplo1~3`·`Prueba`는
  시험용 더미로 보인다. 나머지(`F3`·`BARB`·`EricLostie`)는 판정이 필요하다.
- **절23에 `messages.dat`에만 있는 키 둘** — 게임이 조회하면 원문이 뜬다. 추가분 두 줄로 끝난다.

## 할 일

붙일 수 있는데 안 붙인 검사를 크기 순으로. 넷 다 새 데이터가 필요 없다.

1. **리스트 절(01~13·18·21)의 `es` ↔ `messages.dat` 대조** — 지금은 어긋남 0건이라 잡을 것이
   없지만 **게임 판이 올라 인덱스가 밀리는 것을 잡는 게이트**다. 루프 한 줄 규모.
2. **절13 ↔ `PBS/trainertypes.txt`** — `messages.dat`보다 넓어 위 `Papa`를 잡는다.
3. **미번역 검출(한국어 칸 = 원문 칸)** — 절01~22만 보면 예외가 열 건 안쪽이라 게이트로
   설 만하다. ⚠ 절23은 1,519건이라 그대로는 못 쓴다(엔진 디버그 문자열이 대부분).
4. 절13 ↔ 코퍼스 trtype 열은 적중이 14/196뿐이고 오탐 냄새가 나 2번에 얹는 정도로.
