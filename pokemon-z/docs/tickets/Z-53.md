# Z-53 — 번역 SoT 전수 감사: 코드에 박힌 용어·문안 하드코딩 발굴 (P-3, 중간)

번역쌍이 코드에 살면 정본이 둘이 된다. 유지자 판정이 데이터만 고칠 때 코드 쪽이
낡은 채 프롬프트·화면에 실리는 사고가 실제로 났다 — batch_pages TITLES의
("profesora","교수")가 8/9 「올리비에=박사」 판정을 놓쳐 Z-47 배치에서 회귀 2건
(감사: [2026-08-13 용어 감사는 세션 보고로만 있음 — 박제는 이 티켓 진행 시]).
원칙(유지자 2026-08-13): **"번역의 핵심은 SoT다. 하드코딩 목록이 존재하는 것
자체가 문제다."**

TITLES 자체는 즉시 수선으로 해체됐다(term-pairs.jsonl 이관). 이 티켓은 **나머지
전수**다.

## 할 일

- translate/ 도구 전부 + 스튜디오(review_gui·review_page) + 모드 조립(share/) +
  UI Text KR 경로에서 스페인어→한국어 쌍·한국어 용어 목록·문안이 코드에 박힌 자리
  전수 수색. 즉시 수선의 (b) 분류 목록(번역쌍 아님 판정 — 감시 금칙어·화자 집합·
  판정성 상수)을 출발 재료로 쓰되, 그 분류 자체도 재심한다.
- 각 발견을 셋으로 가른다: 정본 복제(→ SoT 이관) · 판정성 상수(→ 대장 근거 링크
  달아 잔류) · 감시용 목록(→ 잔류, 성격 주석).
- 프롬프트 Term rules 절의 전 항목을 glossary.md 판정과 전수 대조(8/13 감사는
  profesor·capitán·bastión 세 건만 확인 — 나머지 미완).
- 8/9 판정 전후의 세션 트랜스크립트 발췌(용어 판정 논의)는 필요할 때만 — 감사가
  34개 파일까지 좁혀 두고 멈췄다.

## 확장 (유지자 2026-08-13): 정본 자체의 SoT화 + 구조화

감사(발굴·이관)에서 한 발 더 — **정본을 포함한 번역 SoT화와 더 제대로 된 구조화**가
목표다. 갈래 둘:

- **00-maps 안쪽 구조화** — 지금은 머리줄+평평한 (k,v) 나열이라 이벤트·페이지·화자
  구조가 귀속표에만 있다. 정본 안(또는 병행 층)에 그 구조를 앉히는 설계.
- **번역표 바깥 텍스트의 SoT화** — 하드코딩 스크립트 문자열(층③ UI Text KR 치환표,
  층④·⑤ patch_intl EDITS, 그림 베이크 층⑥ 원문 포함)도 번역 정본 체계 안에서
  한곳 관리로 끌어온다. 지금은 층마다 정본이 따로 살아 판정이 한쪽만 고쳐진다.
