# Z-64 — 맹독과 독이 상태이상 표시에서 안 갈린다

**단계** P-2(가능성 확인) · **크기** 작음 · **판정 대기**

유지자 제보 2026-08-16. 조사 결과 **한글화가 만든 결함이 아니라 원작의 사양**이다.

## 확인한 것 (실측, 소스 판독)

- 엔진이 둘을 같은 상태로 친다. `PBStatuses`에 맹독 상수가 없다 —
  `SLEEP=1; POISON=2; BURN=3; PARALYSIS=4; FROZEN=5; CADUCO=6; HEMORRAGIA=7`.
- 맹독 여부는 상태값이 아니라 별도 카운터에만 남는다.
  `PokeBattle_BattlerEffects:200-203`의 `pbPoison(attacker,msg,toxic)`이 둘 다
  `status=POISON`으로 두고 `statusCount`·`effects[PBEffects::Toxic]`에만 표시한다.
- 그림을 고르는 자리는 그 카운터를 안 본다. `PokeBattle_Scene:678-680`이
  `Rect.new(0,(@battler.status-1)*16,44,16)`으로 **상태값만으로** 칸을 고르고,
  파티 요약 화면(`PScreen_Summary:166-170`)도 같다. 전 스크립트의
  `PBEffects::Toxic` 참조 34곳 중 렌더링 코드는 0곳이다.
- **원본 스페인어판도 안 갈린다** — `battleStatuses.png.orig`의 칸은 일곱
  (DOR·ENV·QUE·PAR·CON·CAD·HEM)이고 맹독 전용 칸이 없다. 한글화본도 칸 수·순서가
  1:1로 같다(잠듦·독·화상·마비·얼음·쇠약·출혈).
- 텍스트 층은 이미 맹독을 제대로 옮기고 있다 — `23-script-texts.jsonl:4012`
  「{1}의 몸에 맹독이 퍼졌다!」, `05-moves.jsonl:447` 「맹독」.

## 판정할 것

이것은 번역 결함이 아니라 원작의 기능 한계다. 게이트의 작업 범위 규율상
**손댈지 말지가 먼저 판정할 자리다** — 맹독이 걸린 사실은 대사로 이미 알 수 있으니
아이콘 구분은 기능 개선이라는 읽기도 선다.

손대기로 하면 길은 셋이고 전부 렌더링 코드에 조건 분기를 새로 넣는 **스크립트 수술**을
전제한다.

1. 배지 옆에 작은 표식을 덧그린다 — `PokeBattle_Scene`의 blt 뒤에
   `status==POISON && effects[Toxic]>0` 분기. 요약 화면 쪽 여섯 자리도 같이 손봐야
   화면마다 달라지지 않는다.
2. 맹독용 배지 조각을 PNG로 따로 굽고(⑥층 도구) 분기에서 그것을 그린다 — 1번의 변형.
3. 새 칸을 벌린다 — `battleStatuses.png`는 일곱 칸이 꽉 찼고 `statuses.PNG`의 여덟째
   칸은 포켓러스가 쓰고 있어, 이미지 크기와 오프셋 계산식을 함께 고쳐야 한다. 가장 크다.
