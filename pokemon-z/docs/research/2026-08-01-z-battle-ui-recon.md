# Pokemon Z 전투 화면·상성 판정 해부 (Type Helper 재구현 재료)

> 2026-08-01, 조사 서브 셋(전투 화면 훅·상성 판정 경로·토글/그래픽 재료)의 보고를
> 종합했다. 각 주장의 근거 등급은 서브 보고의 실측/추정/미확인을 그대로 옮겼다.
> **Type Helper 재구현은 이 조사 직후 우선순위가 내려갔다**(사용자 — 게임에 타입
> 표시가 이미 있어서). 이 문서는 그 판단의 근거이자, 다시 열 때의 착수 지점이다.
> 소스 근거의 `zsrc/NNN_*.rb`는 한글패치판 Scripts.rxdata를 섹션별로 푼 것 —
> 재현: 스크래치패드에서 `uv run --with rubymarshal` 판독(이 문서 작성 세션 기록 참조).

## 게임에 이미 있는 것 / 없는 것

**있다 — 데이터박스의 자기 타입 아이콘**(실측). `208_Tipos_Pokemon.rb`(108줄)가
코어의 `PokemonDataBox#refresh`(087:501)를 통째로 재정의해, 상태이상이 없을 때 그
자리에 그 포켓몬 자신의 타입 아이콘(`Graphics/Pictures/types_ico.png`, 24×28 셀
19타입 세로 나열)을 그린다. 일루전 특성까지 반영한다. 사용자가 본 「이미 있는 타입
표시」의 실체다.

**없다 — 상성 정보 전부**(실측, 부재를 전 분기 정독으로 확인). 208에는
`pbTypeModifier`·`pbOpposing` 호출이 0건이다. 기술 정보는 `FightMenuDisplay`의
`@info` 창이 PP와 기술 타입만 적고(087:345-350, 한글패치가 이 파일에 한글 문자열을
직접 박아 넣었다 — 087:2368 「몬스터볼이 없다.」), 기술 이름 색칠·배율 표시·기술
정보 팝업(v20 DBK류) 같은 것은 없다 — `pbFightMenu` 입력 분기 전문에 추가 키가 없다
(087:2417-2447).

## 다시 열 때의 훅 지점 (전부 실측)

- **기술 이름 색칠**: 보이는 버튼은 `Window_CommandPokemon`(투명·화면 밖)이 아니라
  `FightMenuButtons`다(`USEFIGHTBOX=true`, 086:3). 이름은 `FightMenuButtons#refresh`
  (087:392-430)가 그리는데 battler를 안 받는다 — battler는 호출부
  `FightMenuDisplay#refresh`(087:351)의 `@battler`에만 있으므로 **두 메서드를 alias**
  (위에서 심고 아래서 읽기). 상대는 `battler.pbOpposing1`(080:942, 단식 기준).
  외곽선 글자는 `pbDrawOutlineText`(050:963, 8방향 ±2px)가 이미 있다.
- **배율 표시**: 새 창 없이 `@info` 문자열 뒤에 이어 붙이는 것이 자연스럽다(087:345).
- **설정 토글**: 코어에 빈 확장점 `pbAddOnOptions(options)`(143:729-731)가 이미 있어
  코어 무수정으로 옵션을 덧붙일 수 있다. 옛 세이브 호환은 이 게임의 관용구
  `def x; return (!@x) ? 기본값 : @x; end`(numeritos 등 10곳)를 따르면 된다.

## 상성 판정 — 게임의 판정을 그대로 읽는 길 (전부 실측)

- **순수 함수가 있다**: `PokeBattle_Move#pbTypeModifier(type,attacker,opponent)`
  (082:498-582) — 메시지·상태 변경·난수 없음. Roost·타입3·링타겟·틀깨기류 예외·
  프리즈드라이(0x135)와 이 게임 커스텀 함수코드 0x300/0x305(역상성)까지 여기서 처리.
- **단, 특성 면역은 딴 층이다**: 부유·화염흡수·저수 등은 `pbTypeImmunityByAbility`
  (082:372-479)에 있는데 **부작용 덩어리**(랭크 상승·회복·메시지)라 화면에서 부르면
  안 된다. 대신 AI가 점수 계산에 쓰는 **읽기 전용 elsif 사슬**(085:2778-2813)이
  같은 판정을 부작용 없이 한다 — 그 목록을 포팅하는 것이 답이다. AI 목록과 082
  목록의 1:1 대조는 안 했다(미확인 — Well-Baked Body류 누락 의심).
- **기술의 실제 타입은 `move.pbType(move.type, attacker, opponent)`**(082:126-140).
  웨더볼·잠재파워·심판의창 등이 전부 이 문을 지난다. `move.type`을 직접 읽으면 틀린다.
- **눈금**: 단일 상성 원값은 0/1/2/4(2=1배)이고 세 슬롯을 곱해 **합성 8=1배**다
  (082:1406 `damage*typemod/8.0`, 066:22-45 교차 확인). 최종 0·1·2·4·8·16·32라
  4배/0.25배 구분이 정수로 된다.
- 역전 배틀 오버라이드가 있다(`248_Combate_Inverso.rb:239-260`, `@@inverse` 시
  상성 뒤집기) — 표시 계층이 `PBTypes.getEffectiveness`를 직접 부르지 않고
  `pbTypeModifier`를 지나면 자동으로 따라간다.
